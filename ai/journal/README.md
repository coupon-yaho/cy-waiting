# ai/journal — AI 작업 로그

**무엇을 왜 했는가**를 쌓는다. 작업이 끝나면 사라지는 것들을 붙잡아 두는 곳이다.

---

## 1. 왜 남기는가

코드와 커밋은 **무엇을 했는지**는 보여준다. 남지 않는 것은 이것들이다.

| 사라지는 것 | 나중에 치르는 비용 |
|---|---|
| **고려했다가 버린 대안** | 같은 대안을 다시 검토하고 같은 이유로 버린다 |
| **그 판단의 근거** | 근거가 바뀐 줄 모르고 결정만 남아 관성이 된다 |
| **확신이 낮았던 부분** | 어디를 먼저 의심해야 할지 모른다 |
| **검증하지 못한 가정** | 사고가 나야 그게 가정이었음을 안다 |

AI가 작업할 때 특히 크다. 세션이 끝나면 **추론 과정 전체가 사라지고 결과물만 남는다.**
다음 세션의 AI도, 사람도, 그 결과물을 근거 없이 물려받는다.

---

## 2. ADR과 무엇이 다른가

| | 답하는 것 | 되돌리는 비용 | 위치 |
|---|---|---|---|
| **ADR** | 오래 가는 아키텍처 결정 | 설계 회의 | `plan/90-decisions.md` |
| **Journal** | 개별 작업의 판단 | 커밋 하나 | 여기 |

작업 중 ADR급 결정이 나오면 journal에 적고 **`plan/90-decisions.md`로 승격**한다.
승격 시 프론트매터에 `promoted-to: A-9` 를 남겨 추적한다.

**판단이 서지 않으면 일단 journal에 적는다.** 승격은 나중에 할 수 있지만,
적지 않은 것은 복원할 수 없다.

---

## 3. 언제 남기는가

| 상황 | 필수 |
|---|---|
| 코드를 추가·수정한 세션 | ✅ (WF-6) |
| 설계·분석만 한 세션 | ✅ |
| 규칙을 바꾼 세션 | ✅ |
| 리뷰에서 결함을 찾은 세션 | ✅ |
| 오타 수정, 포매팅 | 불필요 |
| 계획서 문구 다듬기 | 불필요 |

**세션당 하나**가 기본이다. 한 세션에서 성격이 다른 작업을 여러 개 했으면 나눈다.

---

## 4. 파일 배치와 이름

```
ai/journal/
├── README.md          ← 지금 이 파일
├── TEMPLATE.md        ← 복사해서 쓴다
│                     색인은 파일이 아니다 — 프론트매터에서 만든다
└── 2026/
    └── 08/
        ├── AIJ-0001-analyze-legacy-admission-logic.md
        └── AIJ-0002-recovery-transition-findings.md
```

- ID는 **전역 연번** `AIJ-####`. 폴더가 갈려도 번호는 이어진다
- 슬러그는 영문 소문자 kebab-case, 3~6단어

---

## 5. 무엇을 쓰는가

템플릿([TEMPLATE.md](TEMPLATE.md))의 여섯 절 중 **셋이 핵심**이다.

| 절 | 왜 중요한가 |
|---|---|
| **왜 (근거)** | 근거가 바뀌면 결정도 바뀌어야 한다. 근거 없는 결정은 관성이 된다 |
| **고려했으나 택하지 않은 것** | 이게 없으면 다음 사람이 같은 길을 다시 걷는다 |
| **확신이 낮은 부분** | 사고가 났을 때 **어디를 먼저 볼지**를 정해 준다 |

나머지 셋(무엇을·검증·다음 사람에게)은 짧아도 된다.

### 잘 쓴 예

> **고려했으나 택하지 않은 것**
>
> - **키별 만료 캐시(Caffeine)** — miss가 나면 그 순간 Redis로 요청이 몰린다.
>   오픈 첫 초에 정확히 피해야 할 상황이라 버렸다.
> - **pub/sub 방송** — at-most-once라 재연결 노드가 놓친 것을 모른다.
>   신선도 판단을 위해 변화가 없어도 매 틱 방송해야 하므로 트래픽 이득도 없다.

### 못 쓴 예

> **고려했으나 택하지 않은 것**
>
> - 다른 방법도 있었지만 이게 나아 보였다.

## 6. 확신도 표기

프론트매터의 `confidence`는 **다음 사람에게 주는 신호**다.

| 값 | 의미 |
|---|---|
| `high` | 검증했고 근거가 명확하다 |
| `medium` | 근거는 있으나 검증하지 못한 가정이 있다 |
| `low` | 판단을 내렸지만 **먼저 의심해야 할 곳**이다 |

`low`를 부끄러워하지 않는다. **낮은 확신을 높다고 적는 것**이 유일한 잘못이다.

`low`인 엔트리는 index에 표시되고, 관련 사고가 나면 가장 먼저 확인한다.

---

## 7. 지난 엔트리는 고치지 않는다

**엔트리는 그때의 판단을 남긴 기록이다.** 계획이 바뀌었다고 과거 엔트리의 페이즈
번호나 결론을 고쳐 쓰면, **왜 그때 그렇게 판단했는지가 사라진다.** 그러면 같은
논쟁이 다시 벌어져도 참고할 것이 없다.

| 대상 | 성격 | 바뀌면 |
|---|---|---|
| `2026/…/AIJ-*.md` | **기록** — 그 시점의 판단 | 손대지 않는다 |
| 작업 로그의 "확인할 것" | **추적표** — 앞으로 할 일 | 계속 갱신한다 |

결론이 뒤집혔으면 **새 엔트리를 쓰고** 이전 것에서 이어지는 맥락을 링크한다.
가정이 해소되면 그것을 적었던 로그에 `✅` 와 근거 ID 를 단다.

오탈자·깨진 링크 같은 것은 고쳐도 된다. **판단과 근거를 바꾸지 않는다**는 뜻이다.

## 8. 되짚기

```bash
# 특정 계획 태스크에 관한 모든 작업
rg 'plan:.*2\.3\.9' ai/journal/

# 확신이 낮았던 판단들
rg 'confidence: low' ai/journal/

# 특정 결정으로 승격된 것
rg 'promoted-to: A-7' ai/journal/

# 커밋에서 되짚기
git log --grep='Refs: CY-145'
```

## 색인은 생성물이다

손으로 유지하지 않는다. `.github/scripts/journal-index.sh` 가 각 로그의
프론트매터를 읽어 만든다.

```bash
.github/scripts/journal-index.sh          # 표준출력으로 본다
.github/scripts/journal-index.sh --check  # 프론트매터만 검사한다
```

**저장소에 커밋하지 않는다.** 손으로 유지하면 동시에 도는 브랜치마다 같은
자리에서 충돌하는데, 그 한 줄의 값은 이미 로그 안에 다 있다 — 사본이 생기면
둘이 갈라지고, 그때부터 CI 가 그 갈라짐을 막느라 일한다.

PR 에서는 **잡 요약**에, `main` 에 들어갈 때는 **Confluence** 에 실린다.
