# 고쳤는데 안 고쳐진 것처럼 보였다

## 증상

봇 PR 의 규약 면제를 개발 브랜치에 병합했는데, 봇 PR 은 그대로 빨갰다.

## 원인

봇이 대상 브랜치를 안 정해 두어 **기본 브랜치를 겨냥한다.** 이 저장소의 기본
브랜치는 릴리스 브랜치다.

그리고 워크플로는 **대상 브랜치에 있는 것**이 돈다. 면제는 개발 브랜치에 있고
봇 PR 은 릴리스 브랜치를 보므로, 그 수정이 애초에 안 닿았다.

## 그 자체가 더 큰 문제였다

사람은 전부 개발 브랜치로 PR 을 여는데 **봇만 릴리스 브랜치로 바로 들어간다.**
브랜치 전략과 어긋나고, 의존성 갱신이 개발 브랜치의 검증을 통째로 건너뛴다.

서드파티 액션의 고정 해시를 바꾸는 갱신도 그 경로를 탄다. 그 고정이 공급망을
지키는 장치인데, 그걸 바꾸는 변경만 검증을 덜 받는 셈이다.

## 확인하지 않았으면 못 봤다

병합하고 "고쳤다" 로 넘어갈 뻔했다. 봇 PR 을 실제로 다시 봐서 여전히 빨간 것을
보고서야 원인이 하나 더 있다는 걸 알았다.

**고쳤다는 말은 그것이 도는 것을 본 뒤에만 할 수 있다.**

## 어떻게 검증했는가

| 확인한 것 | 결과 |
|---|---|
| 봇 PR 의 대상 브랜치 | `main` — 개발 브랜치가 아니다 |
| 설정 파싱 | 두 생태계 다 `develop` |
| 훅 자기검증 | 81건 통과 |

## 고려했으나 버린 것

- **면제를 릴리스 브랜치에도 넣기.** 증상은 사라지지만 봇이 릴리스 브랜치로
  바로 들어가는 것은 그대로다. 원인이 아니라 증상을 덮는다.
- **봇을 끄기.** 서드파티 액션의 고정 해시는 손으로 올리면 영영 안 올라간다.

## 남은 것

**이미 열린 봇 PR 아홉 개는 대상이 릴리스 브랜치인 채로 남는다.** 봇이 다음
주기에 다시 열거나, 닫고 새로 열게 해야 한다.
