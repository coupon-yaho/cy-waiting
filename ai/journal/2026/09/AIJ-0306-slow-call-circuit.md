# 느린 호출로 여는 서킷을 처음 밟는다

## 무엇을

C8 은 응답 상한 300ms 가 느린 호출 임계보다 짧아 서킷이 늘 타임아웃으로 열린다. 느린 호출 비율
배선을 어느 행위 시험도 안 밟았다. 설정 게터 시험은 값이 실렸는지만 본다.

C8b 를 붙였다. 뒷단이 짝수 회원에게만 500ms 늦게 200 을 내고, 응답 상한 2초·느림 임계 200ms·표본
하한 4 로 돌린다. 정상 구간 뒤 서킷을 리셋해 창을 비우고 빠른 것과 느린 것을 반씩 보내면 비율이
정확히 문턱 50 이다. 판정은 느린 호출 초과 이벤트 1회·실패 초과 0회·실패 0건, 뒷단 유입 0, 202,
열린 채로 안 굳음, 중복 발신 0 이다.

**창을 비우는 이유.** 정상 구간의 빠른 호출이 창에 남으면 비율이 문턱 아래로 묽어져, 몇 건째에
열렸는지로 문턱을 못 잰다.

## 어떻게 검증했나

- C8b 통과, 스텁을 바꾼 뒤 C8·C9c 그대로 통과
- 프로브 1: 느린 호출 비율 문턱을 100 으로 올리면 안 열려 빨개진다
- 프로브 2: 응답 상한을 300ms 로 내리면 503 이 섞이고 실패율로 열려 빨개진다. 처음에 연결 상한을
  안 내려 기동이 막혔다 — 연결 상한이 응답 상한보다 짧아야 한다

## 남은 것

- 운영값(표본 20, 임계 1900ms)에서 느린 호출로 여는 구간은 아직 안 잰다
