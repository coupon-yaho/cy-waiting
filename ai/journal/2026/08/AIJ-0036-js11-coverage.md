# 예외를 파일에 걸었더니 두 구멍이 남았다

## 무엇이 잘못돼 있었나

`AIJ-0034` 에서 `JS-11` 을 훅에 넣으며 **"`TS-2` 와 `JS-11` 의 경계를 '운영 코드 /
시험' 으로 그었다"** 고 적었다. 그건 기록된 결정이었고 실수가 아니었다.

**이번에 그 경계를 옮긴다.** 파일 단위 예외가 그 안의 **모든 선언 종류**를 함께
면제하기 때문이다. `TS-2` 가 허용하는 것은 시험 *이름* 과 헬퍼인데, 예외를 파일에
거니 클래스·레코드명까지 딸려 나갔다.

구멍은 둘이었다. 실측으로 확인했다 — 훅에 직접 넣어 돌린 결과다.

| 구멍 | 원인 |
|---|---|
| 시험 파일의 타입 이름 | `is_test` 면 `JS-11` 을 **파일 단위로** 건너뜀 |
| 빌드 스크립트 | `check-java.sh` 는 `.java` 만 받는다. 어떤 검사도 안 봤다 |

## 무엇을 했나

**범위를 파일이 아니라 선언 종류로 그었다.**

시험 파일에서는 `class`·`record`·`interface`·`enum` **바로 뒤 토큰**과 그 뒤 제네릭
인자만 본다. 메서드·헬퍼·지역변수는 그대로 통과한다.

빌드 스크립트는 `.github/scripts/build-script-identifiers.sh` 를 새로 만들었다.
`def`·`task`·타입 있는 선언·`ext` 대입·`tasks.register('이름')` 을 본다. **CI 와
러너가 같은 스크립트를 부른다.**

## 검사가 나보다 정확했다

정규식으로 훑어 `class 필수값`·`class 음수` 둘을 찾았는데, 검사를 넣고 돌리니
**두 개가 더 나왔다** — `class IDLE에줄이없다`, `class pollScale유한값`. 영문과
한글이 섞인 이름이라 내 패턴이 안 걸렀다. 손으로 훑은 결과를 믿었으면 절반만 고친
채 "다 됐다" 고 적었을 것이다.

## 줄 단위 판정은 양쪽으로 샜다

처음엔 "마스킹 결과에 비 ASCII 가 남았고 그 줄이 선언처럼 생겼으면 위반" 으로
짰다. 2차 검토가 우회 일곱을 실증했다.

| 새던 것 | 왜 |
|---|---|
| `@DisplayName("표시") class 한글 {` | 어노테이션의 `(` 를 정규식이 못 넘는다 |
| `void t() { class 한글로컬 {} }` | 선언이 줄 맨 앞이 아니다 |
| `@interface 한글어노테이션` | 뒤에 타입 키워드가 없다 |
| `strictfp class 한글엄격` | 수식어 목록에 없다 |
| 선언이 줄바꿈됨 | 키워드와 이름이 다른 줄 |
| `class Box<한글타입>` | 제네릭 인자 |

반대 방향으로도 샜다 — `class Ok { int 한글필드; }` 는 타입명이 영문인데 **차단**
됐다. 줄 단위라 선언 줄에 얹힌 다른 한글까지 물었다.

**토큰 단위로 바꾸니 일곱이 한꺼번에 닫히고 오탐도 사라졌다.** 수식어·어노테이션·
줄바꿈·중첩 깊이에 무관해진다. 여섯을 각각 프로브로 걸었고, 오탐 쪽도 통과
프로브로 고정했다.

## 고려했으나 버린 것

- **Groovy 를 제대로 파싱한다.** `ext[동적이름]` 까지 잡을 수 있지만 파서를 들이는
  값어치가 아직 없다. 선언 자리만 보고 **한계를 스크립트 머리에 적었다.**
- **시험 예외를 `@Nested` 어노테이션 기준으로 긋기.** 어노테이션이 없는 중첩
  클래스와 최상위 클래스가 빠진다. 선언 종류가 더 정확한 축이다.
- **빌드 스크립트 검사를 `check-java.sh` 안에 넣기.** 그 훅은 `Write`·`Edit` 로 쓴
  `.java` 만 받는다. `.gradle` 을 태우려면 훅 배선을 바꿔야 하고, 그건 이 티켓
  범위 밖이다 — 그래서 **아래 "남은 위험" 에 남는다.**

## 어떻게 검증했는가

프로브 28개. 로케일 3종(`ko_KR.UTF-8`·`C.UTF-8`·`en_US.UTF-8`)에서 **112/0**.

- 시험 타입명: 차단 3 + 우회 회귀 6 + **통과 3**(한글 시험 이름·헬퍼·영문 타입명에
  얹힌 한글). 통과 쪽이 없으면 `TS-2` 를 깨뜨리는 방향으로 넓혀도 안 깨진다.
- 빌드 스크립트: 차단 5 + 통과 2. **되돌려서 확인했다** — 검사 대상 경로를 없는
  곳으로 바꾸니 프로브 둘이 죽는다.
- Kotlin DSL: 차단 3 + 통과 1. `find` 에 `.kts` 를 넣고 문법을 안 보면 그 파일이
  "검사했다" 로 세어져 fail-closed 도 안 걸린다 — 리뷰가 짚었다.

**태스크 이름을 마스킹 전에 뽑은 것이 오탐을 만들었다.** `// tasks.register("한글")`
같은 주석 속 예시와 문자열 안에 든 코드까지 위반으로 보고했다 — "주석과 문자열의
한글은 정상" 이라는 규칙을 검사 자신이 깬 것이다. 문자열 리터럴을 만나는 **그
자리**에서 앞의 코드가 `register(` 인지 보고 뽑도록 옮겼다. 주석은 그 지점에
도달하지 않고, 문자열 안의 문자열은 바깥 것에 통째로 먹힌다.

한 줄짜리 `ext { 한글 = 1 }`, 소문자 원시 타입(`int 한글`), 제네릭 타입 인자
(`register<한글타입>`)도 함께 닫았다. 앞의 둘은 여는 줄에서 `next` 로 빠지거나
타입 패턴이 대문자로 시작하는 것만 봐서 샜다.

검사가 볼 것이 하나도 없으면 **실패**하게 했다. 경로 오인이나 `.kts` 전환으로
대상이 사라져도 "통과" 를 찍으면 그때부터 이 게이트는 영원히 초록이다.

## 확신이 낮은 부분 · 남은 위험

**`build.gradle` 을 고치는 순간에는 아무것도 안 돈다.** `PostToolUse` 훅은
`check-java.sh`·`check-lua.sh` 뿐이라 `.gradle` 편집에 즉시 피드백이 없다. PR 과
CI 에서만 걸린다 — 색인 표에 그 시점을 `PR`·CI 로 적었지만, 훅 단계의 공백은 남아
있다.

**클로저 파라미터와 동적 이름은 못 본다.** `def x = { 한글 -> ... }` 같은 것이다.
지금 저장소에 그런 코드가 없어 실해는 없지만, 규칙만 읽은 사람은 막힐 거라 믿는다.

## 다음 사람이 알아야 할 것

**검사를 넓힐 때 예외를 파일에 걸지 않는다.** 파일 단위 예외는 그 안의 모든 선언
종류를 함께 면제해서, 정작 막으려던 것이 조용히 빠진다. 예외는 **선언 종류**에
건다 — 그래야 무엇이 면제됐는지가 규칙에 드러난다.

**줄 단위 정규식으로 선언을 고르지 않는다.** 어노테이션·수식어·줄바꿈이 조금만
달라도 새고, 반대로 같은 줄의 무관한 것까지 문다. 토큰을 세는 편이 짧고 정확하다.
