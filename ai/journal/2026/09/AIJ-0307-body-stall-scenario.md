# 헤더는 오고 본문이 안 끝나는 뒷단

## 무엇을

CY-870 은 이 변종에서 C18 의 세 판정이 거짓 초록이라 적었다. 같은 시나리오를 요구하는 CY-714 가
이미 있었다 — 중복이다. 그 뒤 CY-633 에서 본문 쓰기에 총 시간 상한(응답 상한의 두 배)이 붙어 이제
매달리지는 않는다. C18-b 를 붙였다. 스텁이 헤더 200 과 첫 조각만 보내고 본문을 안 끝낸다.

## 무엇을 판정하나

- 본문 상한이 보낸 수만큼 끊었다. 클라이언트 시한에 걸려도 잘림으로 보이므로 계수로 가른다
- 상한이 응답 상한의 두 배로 실리는지는 라우트 단위 시험이 필터의 값을 직접 읽어 잰다. 처음에는 걸린 시간을
  위아래로 묶었는데 원격 리뷰가 실시간 경과는 러너 지연에 흔들린다고 짚어 옮겼다
- **결함 고정:** 사용자는 잘린 200 을 받는다 (CY-713)
- **결함 고정:** 서킷 실패 0, 성공이 보낸 수만큼 는다 (CY-710). 실패 0 만 보면 아예 안 센 경우도 초록이다
- 회복하면 온전한 200, 중복 발신 0

## 틀렸던 것

처음에 이 둘을 "CY-633 이 받아들인 한계" 로 적었다. **아니다.** AIJ-0135 와 계획서 6장이 결함으로 적고
CY-710~713 을 달았고, 라우트 배선 주석도 "끊는 자리가 서킷 안쪽이어야 한다" 고 적는다. 로컬 리뷰가
짚었다. 결함 고정으로 고치고 티켓을 인용했다.

## 어떻게 검증했나

- C18-b 통과
- 프로브: 주입을 빈 동작으로 바꾸면 끊은 수 0, 온전한 200 으로 빨개진다

## 남은 것

- 본문만 멎는 뒷단은 서킷이 영영 안 연다 (CY-710)
- 격벽이 본문 구간을 안 세 커넥션이 쌓이는 것(CY-711)과 끊긴 코호트의 동시 복귀(CY-712)는 요청을
  순차로 보내 못 잰다
