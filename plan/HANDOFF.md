## 6. 되풀이되는 병 — 초록인데 아무것도 안 재는 자리

이번 구간의 리뷰가 **매번** 같은 것을 찾았다. 새 시나리오를 쓸 때 이 목록을
먼저 훑는다.

1. **관측만 하고 판정에 안 걸린 값** — 대입만 되고 아무 `violations(...)` 에도
   안 들어가는 변수. C9·C12·C18 에서 각각 나왔다
2. **판정이 다른 대상을 본다** — C9 의 회복 판정이 대조군 목록을 봤다
3. **비교 집합에서 실패 사례를 뺀다** — C12 의 자리 판정이 사라진 사람을 제외해
   정의상 안 깨졌다
4. **0 == 0** — C18 의 격벽 판정이 "끝난 뒤 0" 만 봐서 격벽을 들어내도 통과했다
5. **범위만 보고 값이 갈리는지는 안 본다** — C18 의 다시 올 시각
6. **기다린 것과 판정이 그것을 본 것은 다르다** — C5 가 낡음을 기다렸지만 판정이
   그 갈래를 밟았는지는 안 쟀다
7. **픽스처가 프로덕션에 없는 상태를 만든다** — 줄 점수를 100 부터 심어 스위퍼가
   그 줄을 아예 못 봤다. `QueueSeed` 로 해결
8. **시험이 프로덕션이 안 부르는 경로를 부른다** — CY-859 에서 고쳤다고 적은 것이
   실제로는 한 번도 안 돌았다

**대응은 하나다.** 판정을 쓴 직후 **뮤턴트를 직접 넣어 죽는지 본다.** 안 죽으면
그 사실을 저널과 계획서에 적는다 — 판정을 지우지 말고, 재는 척하는 자리임을
남긴다.

## 7. 작업 절차 요약

[../CLAUDE.md](../CLAUDE.md) 5절이 원본이다. 이 구간에서 실제로 밟은 순서:

```
0. 티켓 → 브랜치  feature|bugfix/CY-<번호>-<영문-슬러그>   ← 접두사가 규칙에 있다
1. RED → GREEN → (REFACTOR)
2. 뮤턴트를 직접 넣어 판정이 무는지 확인
3. 저널 + 계획서 정렬 (못 재는 것을 반드시 적는다)
4. .claude/hooks/review-branch.sh
5. 에이전트 리뷰 → 반영
6. ./gradlew build jacocoTestCoverageVerification · chaosTest
7. git rev-parse HEAD > .claude/.agents-reviewed   ← 별도 호출로 쓴다
8. PR → CI → Qodo(/review 는 workflow_dispatch 로 부른다) → 반영 → 머지
9. Jira 완료 처리
```

**주의할 것**
- 브랜치 하나에 티켓 하나. 섞이면 기계 검사가 막는다
- 커밋 제목은 50칸 (한글은 두 칸으로 센다). 푸터에 `Refs: CY-###`
- `src/main` 은 영문 식별자만. 한글은 주석에, 시험·픽스처는 예외
- Javadoc 과 `//` 를 같은 선언에 겹쳐 쓰지 않는다
- Qodo 는 코멘트로 안 불린다. `gh workflow run "Qodo 리뷰" -f pr=<번호> -f command=review`
