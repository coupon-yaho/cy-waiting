페이즈 Exit Gate를 판정한다. 대상 페이즈: $ARGUMENTS (없으면 진행 중인 페이즈)

## 절차

1. `plan/0N-*.md` 의 **Exit Gate** 절을 읽는다
2. 각 기준(G*)에 대해 **실제로 측정**한다 — 코드를 읽고 "될 것 같다"는 판정이 아니다
   - 테스트·커버리지·뮤테이션: 실행해서 수치를 얻는다
   - 부하·카오스 기준: 해당 잡을 돌린다
   - 실행할 수 없는 항목은 **"측정 불가"로 표시**한다. 통과로 세지 않는다
3. 기준별로 **실측치와 판정**을 표로 정리한다

## 판정 규칙

| 상황 | 조치 |
|---|---|
| 전부 통과 | `chore(gate): Phase N 게이트 통과` 커밋. **바디에 실측치를 남긴다** |
| 하나라도 미달 | 다음 페이즈를 시작하지 않는다. 병행 착수도 금지 |
| 기준이 부적절해 보임 | **기준을 낮추지 말고** `plan/90-decisions.md` 에 결정 항목으로 올린다 |

**타협 불가 항목**: 초과 발급 0, 순번 역행 0.
이 둘이 깨지면 제품이 성립하지 않는다. 어떤 사정으로도 완화하지 않는다.

## 게이트 커밋 형식

```
chore(gate): Phase 2 게이트 통과

분기 커버리지 100% / 뮤테이션 생존 4.2%
R1 · F1 · F4 · F8 시나리오 통과
속성 테스트: 배분 10만회 크레딧 초과 배분 0, 순위 10만 시퀀스 역행 0

Refs: CY-48
```

형식과 이유는 `ai/rules/60-workflow.md` WF-4.
판정 결과는 Confluence 에 남기고 커밋에는 링크만 둔다.
