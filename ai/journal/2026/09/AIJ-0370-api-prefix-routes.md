# 라우트 경로를 /api/ 아래로 강제한다

## 무엇을

라우팅 규칙의 경로는 모두 `/api/` 로 시작해야 한다. 아니면 두 인증 모드 모두 기동을 멈춘다. CY-980 에서 인증
모드에만 걸어 둔 같은 검사는 규칙 쪽으로 합치면서 뺐다.

## 왜 (근거)

CY-980 에서는 "인증을 켰는데 라우트가 신원 필터 밖이면 토큰 없이 남의 이름을 쓴다" 만 보고 인증 모드에서만 막았다.
다시 보니 `/api/**` 에만 걸리는 것은 신원 필터 하나가 아니다. 남용 리미터와 교차 출처 설정도 같은 범위를 본다.
헤더 모드에서도 밖의 경로는 형식 검사 없이 깨진 회원 헤더를 뒷단에 흘리고, 회원·주소별 초당 상한도 안 받는다.
그래서 모드와 무관한 규칙의 성질로 옮겼다.

기본 규칙과 저장소 안의 설정은 모두 `/api/v1/...` 라 바뀌는 배포가 없다.

## 버린 것

- **필터 범위를 규칙의 경로에서 만든다.** 필터 셋의 범위를 설정에서 끌어오면 어떤 경로를 적어도 보호가 따라간다.
  다만 순번 조회처럼 라우트를 안 타는 경로도 같은 범위로 보호해야 해서, 범위가 두 곳에서 정해진다
- **헤더 모드는 경고만 남긴다.** 경고는 기동 로그에 묻힌다

## 어떻게 검증했는가

`/v2/...`, `/api`, `/apix/...` 가 모두 기동에서 막히는지 규칙 시험으로 본다. 기존 규칙 시험의 경로는 `/api/` 아래로
옮겨, 다른 검사를 보는 시험이 이 검사에 먼저 걸리지 않게 했다. `./gradlew build` 와 기계 검사를 통과했다.

## 다음 사람이 알아야 할 것

`/api/` 를 바꾸려면 필터 셋(신원, 남용 제한, 교차 출처)의 범위와 이 검사를 같이 옮긴다.
