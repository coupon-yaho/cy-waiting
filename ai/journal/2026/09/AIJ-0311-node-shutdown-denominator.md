# 실제 노드를 닫아 등록 해제로 분모가 내려오는지

## 무엇을

C6 은 레디스 해시를 고쳐 노드 소실을 흉내 내 죽는 노드 자신의 드레인·등록 해제를 안 밟는다. 두 번째 노드
픽스처를 띄웠다 닫아, 남은 노드의 분모가 등록 해제 경로로 곧 내려오는지 잰다.

## 한계를 어떻게 정했나

등록 해제가 돌면 다음 하트비트부터 한 대로 세어 감소 확정 세 틱 뒤 내려온다. 빠지면 표 신선도가 지나야
세지 않으니 그만큼 늦다. 두 경우를 실제로 재서 사이에 한계를 뒀다.

- 해제 있음 2.9초, 해제를 빈 동작으로 바꾸면 5.9초. 한계 4.5초로 양쪽에서 1.5초 가까이 떨어져 있다
- 내려온 뒤 3초 동안 다시 오르지 않는지도 본다

## 로컬 리뷰가 고친 것

시간으로만 가르면 종료가 느린 날 "등록 해제가 안 돌았다" 로 원인을 잘못 짚는다. 해제 없는 쪽 여유도 하트비트
위상에 따라 0.5초까지 줄어든다. 닫은 직후 레디스 등록에서 노드 필드가 하나만 남았는지를 직접 보고, 시간은 닫힌
뒤부터 재 감소 확정이 늦어지는 회귀만 거르게 했다.

## 뗀 것

티켓은 레디스 흔들림을 겹친 판과 리더만 정상인 비대칭 판도 적었다. 한쪽 노드만 레디스를 못 쓰게 하려면 노드별
프록시가 필요해 새 하위 작업으로 뗐다 (CY-931).
