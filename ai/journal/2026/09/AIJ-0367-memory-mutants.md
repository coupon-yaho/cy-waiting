# 메모리를 태우는 뮤턴트를 먼저 죽인다

## 무엇을

v0.8.0 의 main 뮤테이션을 멈춘 뮤턴트 둘이 메모리를 태우기 전에 시험이 죽이게 했다.

## 왜 (근거)

**점수는 넘었는데 게이트가 빨갰다.** 3,563 개 중 3,231 개를 죽여 90.68% 로 임계 90% 를 넘었다. 그런데 둘이
`MEMORY_ERROR` 로 끝났고, 가드는 그 상태를 판정 없음으로 쳐서 비율을 거부했다.

**둘 다 뮤턴트가 무한 루프를 만든 것이었다.** 스케줄러의 다음 지연에서 조건이 뒤집히면 0 초를 쉬고 도는
루프가 되고, 가상 시간으로 재는 시험은 같은 시각에서 영원히 돌아 메모리만 태운다. 유입 기록기에서 반복의
증가가 감소로 바뀌면 루프가 안 끝나고 표를 채운다. 실질은 시험이 잡은 것이고 PIT 도 이 상태를 잡힘으로
센다. 하지만 **가드는 러너 탓의 메모리 부족과 뮤턴트 탓을 가를 수 없다.** 그래서 가드를 느슨하게 하지 않고,
뮤턴트가 메모리에 닿기 전에 단언으로 죽게 했다.

## 무엇을 바꿨나

- 스케줄러의 다음 지연을 시험이 직접 본다. 0 을 내는 순간 단언이 깨진다
- 기록기는 증가 연산자 대신 범위로 돈다. 루프가 안 끝나는 뮤턴트가 생길 자리 자체가 없다

## 어떻게 검증했는가

두 클래스만 대상으로 PIT 를 돌렸다. 판정 없는 뮤턴트가 0 이다. 남은 생존 둘은 같은 값일 때 어느 쪽을 골라도
결과가 같은 경계 뮤턴트라 등가다.

## 다음 사람이 알아야 할 것

**`MEMORY_ERROR` 가 나오면 가드를 풀지 말고 그 뮤턴트가 무엇을 폭주시켰는지 본다.** 대개 끝나지 않는 루프이고,
단언 하나로 먼저 죽일 수 있다.
