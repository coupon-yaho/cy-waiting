## 1. 무엇을 만드는가

Spring WebFlux 기반 **적응형 대기열 게이트웨이**. 뒷단은 쿠폰 서비스 N대.
도메인은 대규모 선착순 쿠폰 발급.

| # | 요구사항 | 실현 |
|---|---|---|
| **R1** | 부하 없는 쿠폰은 대기열 없이 즉시 통과, 몰리는 쿠폰만 대기열 | Phase 2 |
| **R2** | 뒷단 N대의 가용량 비율대로 분산 (200/40/120 → 그 비율로) | Phase 4·9 |
| **R3** | 매진 쿠폰은 Redis·백엔드를 거치지 않고 게이트웨이가 종결 | Phase 7 |
| **R4** | 피크 100K / 동시 대기 20,000에서 무너지지 않음 | Phase 10 |
| **R5** | **장애 진입·유지·회복 전 구간에서 정합성과 공정성 유지** | Phase 8 |
| **R6** | 대기 순위·ETA 제공. 근사 허용, **단조성은 타협 불가** | Phase 2·10 |

R5가 무게중심이다. 장애 중 동작만이 아니라 **회복 전이**까지 카오스로 판정한다.

> **각 요구사항의 출처·근거·비목표·제약·가정은 [00-requirements.md](00-requirements.md) 에 있다.**
> 위 표는 요약이다. 무엇을 왜 만드는지 판단이 필요할 때는 그 문서를 본다.

## 2. 페이즈 목표 — 한눈에

**각 페이즈는 아래 수치를 넘겨야 닫힌다.** 못 넘기면 다음 페이즈를 시작하지 않는다.

> **지금은 Phase 2 종료 판정.** Phase 1 은 닫혔고, Phase 2 의 태스크와 종료
> 게이트가 다 찼다. 다음은 Phase 3 이다.

| # | 페이즈 | Goal (한 문장) | 통과 수치 |
|---|---|---|---|
| **1** ✅ | [Foundation](01-foundation.md) | 코드를 쓰기 전에 갖춰야 할 것만 세운다 | 빌드 CI 통과 · 규약 위반 커밋 거부 · 품질 임계 미달 시 빌드 실패 · 훅 자기검증 전건 통과 |
| **2** ◀ | [Domain Core](02-domain-core.md) | **한산한 쿠폰이 대기열 없이 통과한다 (R1)** | 브랜치 100% · 뮤테이션 생존 ≤10% · 크레딧 초과 배분 0/10만회 · 순위 역행 0/10만회 |
| **3** | [Redis Adapter](03-redis-adapter.md) | 큐 순서의 유일성과 단조성이 장애에서도 깨지지 않는다 | 동시 등록 100 → 자리 1개 · `kill -9`·승격 후 순서 역행 0 · 클러스터 모드 전 스크립트 실행 |
| **4** | [Control Plane](04-control-plane.md) | 배분이 리더 하나에서만 돌고 낡음을 두 종류로 구분한다 | 10노드 → 배분 1대 · 리더 승계 ≤3틱 · 틱 지연 p99 <100ms |
| **5** | [Data Plane](05-data-plane.md) | **판정 경로의 Redis 왕복이 0이다** | 통과 경로 Redis 명령 0건(계측) · 미지 쿠폰 1만건 → 키 증가 0 · 위조 토큰 403 · 503 재시도 분산 ≥0.5s |
| **6** | [Protection](06-protection.md) | **요청 경로가 뒷단 장애에 버티고, 그것이 실측으로 증명된다** | 오버헤드 p99 <5ms · 한산한 쿠폰 큐 등록 0건(실부하) · 뒷단 정지 시 물리지 않음 · 쿠폰 2,000개 격벽 메모리 유계 · 종료 중 5xx 0 · 동시 조회 1만 → 뒷단 1건 |
| **7** | [Queue Lifecycle](07-queue-lifecycle.md) | 큐에서 나가야 할 사람이 반드시 나간다 (R3) | 매진 후 1폴링 내 종료 · 이탈 30%에서 크레딧 낭비 <5% |
| **8** | [Resilience](08-resilience.md) | **장애가 걷힌 뒤 스스로 정상으로 돌아온다 (R5)** | 13+3 시나리오 3단계 전부 통과 · 초과 발급 0 · 순위 역행 0 · 회복 버스트 ≤1.2배 |
| **9** | [Routing](09-routing.md) | **가용량 비율대로 트래픽이 흐른다 (R2)** | 유입 비율 오차 ≤±15% · 열화 인스턴스 5초 내 배제 · in-flight 누수 0 |
| **10** | [Scale-out](10-scale-out.md) | 피크 100K RPS 와 동시 대기 20,000 을 견딘다 (R4) | 100K 지속 60초 5xx <0.1% · 노드 증설 효율 ≥70% · 노드별 ops 편차 ≤±20% · 순위 단조성 위반 0 |

> **Goal 과 Exit Gate 의 관계**: Goal 은 "무엇을 이루는가"를 한 문장으로,
> Exit Gate 는 그것을 **어떻게 측정해 판정하는가**를 항목별로 적는다.
> 위 표의 통과 수치는 각 페이즈 Exit Gate 의 대표 항목만 뽑은 것이다.

## 3. 왜 제로베이스인가

```
1 ──┬── 2 ──┬── 4 ──────┬── 7 ── 8 ──┬── 9
    │       │           │            │
    └── 3 ──┴── 5 ── 6 ─┘            └── 10
```

**Phase 8(회복력)이 9·10보다 앞선다.** 회복력이 검증되지 않은 시스템을 확장하면
장애 반경만 커진다.

### 배포 순서상의 위험

**Phase 2를 Phase 9 없이 배포하면 백엔드 위험이 늘어난다.** Phase 2는 한산한
쿠폰의 통과량을 0에서 `globalCredit/N`으로 올리는데, 라우팅은 여전히 라운드로빈이라
가장 약한 인스턴스가 자기 여유를 넘는 몫을 받는다.

→ `waiting.admission.idle-credit-ratio` 를 0.7로 시작하고 Phase 9 완료 후 1.0으로 올린다.
**tier 1(한산한 쿠폰별) 상한에만 건다** (B-13). 값은 `gw:tunables` 로 배포 없이 바꾼다 (P-1).

## 5. 태스크 명세 형식

**태스크는 그것만 읽고 착수할 수 있어야 한다.** 설계를 재도출해야 한다면
그 태스크는 아직 명세가 아니다.

각 태스크가 반드시 담는 것:

| 항목 | 왜 필요한가 |
|---|---|
| **산출물** | 어느 파일을 만들거나 고치는가 |
| **근거** | 어느 설계 절·결정 ID·journal 이 이 태스크를 요구하는가 |
| **RED** | 먼저 쓸 실패 테스트를 **한 문장**으로 — 그대로 테스트 이름이 된다 |
| **GREEN** | 통과시킬 최소 구현 |
| **완료** | 기계적으로 확인 가능한 종료 조건 |

담지 않는 것: 설계 재설명(로 링크), 소요 시간 추정.

### 번호 두 종류를 섞지 않는다

| 번호 | 기준 | 예 |
|---|---|---|
| **절 번호** | **문서 안의 위치** | `04-control-plane.md` 의 `## 6. Task` → `### 6.1 스냅샷 홀더` |
| **태스크 ID** | **페이즈** | 그 절 안의 태스크는 `4.1.1`, `4.1.2` … |
| **게이트 ID** | 페이즈 | `G4.1` |

**문서마다 `## Task` 가 몇 번째 절인지 달라서 둘이 어긋난다.** Phase 2 는 `## 4. Task`
아래 `### 4.2` 에 `2.2.x` 가 있고, Phase 4 는 `## 6. Task` 아래 `### 6.1` 에 `4.1.x` 가 있다.
**태스크 ID 만 페이즈를 따르면 되고**, 절 번호는 그 문서 안에서만 의미가 있다.

게이트의 "검증" 열과 문서 간 상호 참조는 **항상 태스크 ID** 를 쓴다 — 절 번호는
문서가 개편되면 바뀐다.

### 상세화 시점

| 페이즈 | 상세 수준 | 이유 |
|---|---|---|
| 착수 중 · 다음 착수 | **완전 명세** (위 5항목) | 지금 실행한다 |
| 그 이후 | 태스크 제목 + 근거 링크 | 앞 페이즈 결과에 따라 바뀐다. 지금 쓰면 버려진다 |

**페이즈 진입 시 그 페이즈를 완전 명세로 승격**하는 것이 첫 작업이다.
현재 완전 명세: **Phase 1, Phase 2**.

## 6. 페이즈 게이트

1. **모든 항목이 자동 검증**되어야 한다. "확인했다"는 통과가 아니다
2. **하나라도 미달이면 다음 페이즈를 시작하지 않는다.** 병행 착수도 금지
3. 기준이 부적절해 보이면 **낮추지 말고** [90-decisions.md](90-decisions.md)에 올린다
4. 통과는 `chore(gate): Phase N 게이트 통과` 커밋으로 표시하고 **본문에 실측치**를 남긴다

**타협 불가**: 초과 발급 0, 순위 역행 0. 이 둘이 깨지면 제품이 성립하지 않는다.
