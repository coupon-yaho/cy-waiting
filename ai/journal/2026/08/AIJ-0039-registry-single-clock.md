# 판정을 두 곳에 두었더니 시계도 둘이 됐다

`AIJ-0038` 의 결론을 뒤집는다. 그때 적은 "노드별 신선도를 자바에서 센다" 가 틀렸다.

## 무엇이 잘못돼 있었나

신선도 판정이 **두 곳**에 있었다.

| | 하트비트 스크립트 | 레지스트리 |
|---|---|---|
| 시계 | 레디스 서버 | **노드 로컬** |
| 임계 | `reapAfter` | `staleAfter` |
| 낡은 항목 제거 | 매 틱 | **없음** |

같은 정책의 사본 둘이고, 사본은 갈라진다. 더 나쁜 것은 **한 판정 안에서 두 시계를
뺐다**는 점이다 — 인자로 받는 하트비트 시각은 서버 것인데 비교 대상은 로컬
`Clock` 이었다. 노드 시계가 임계만큼 뒤지면 모든 항목이 항상 낡아 분모가 영영
1 이 되고, 앞서면 죽은 노드가 영영 세어진다.

**시험은 이 상태를 만들 수 없었다.** 두 시계에 같은 `MutableClock` 을 넣었기
때문이다. 시계를 주입해 고정한 것은 맞았지만, 시계가 **둘**이라는 사실을 픽스처가
지워 버렸다.

## 무엇으로 바꿨나

**판정은 스크립트 하나에 둔다.** 유일한 시계를 그쪽이 갖고 있다. 레지스트리는
`seen`·`staleAfter`·`Clock` 을 전부 버리고 **분모 하나**만 든다.

그러면 자바 쪽 해시가 배포 이력만큼 자라던 문제도 같이 사라진다 — 애초에 항목을
안 들고 있다.

## 개별 신선도만으로는 F5 가 안 지켜진다

이게 이번에 새로 배운 것이다.

레디스가 임계보다 오래 끊겼다 돌아오면 **모든 항목이 낡은 상태**다. 노드들이
하나씩 붙는 동안 스크립트가 세는 값이 1, 2, 3… 으로 올라온다. 그 틱의 총 통과는

```
C·(1/1 + 1/2 + … + 1/10) ≈ 2.9·C
```

회복 버스트 허용치가 1.2배인데 세 배 가까이 된다. **회복이 곧 2차 장애다.**

개별 항목의 신선도에만 비대칭을 걸면 이걸 못 막는다. **집계값 자체에도** 걸어야
한다 — 증가는 한 번 보면 즉시, 감소는 연속으로 봐야 확정한다. 관측 실패는 감소가
아니므로 연속 카운터를 되돌린다.

## 콜드 스타트에 1 을 쓰면 안 된다

첫 관측 전 분모를 1 로 두면, 10대 운영 중 11번째가 뜨는 순간 그 노드 혼자
크레딧 전부를 자기 몫으로 쓴다. 총합이 `1.9·C` 다.

`AIJ-0038` 이 스스로 "관측 실패의 안전한 방향은 가장 관대한 쪽이 아니다" 라고
써 놓고, 콜드 스타트에서 정확히 가장 관대한 값을 골랐다. 예상 레플리카 수를
설정으로 받는다 — 틀리더라도 **큰 쪽으로** 틀린다.

## 종료 단계를 거꾸로 알고 있었다

`SmartLifecycle` 의 phase 를 "낮을수록 먼저 멈춘다" 로 알고 `Integer.MIN_VALUE+1`
을 줬다. **반대다.** 스프링은 내림차순으로 멈추므로 그 값은 가장 **나중에** 멈춘다.

`LettuceConnectionFactory` 가 `SmartLifecycle` 이고 phase 가 `0` 이다. 즉 커넥션이
먼저 닫히고, 그 뒤에 도는 등록 해제는 **매번 실패한다.** 이 티켓이 만든 기능이
프로덕션에서 한 번도 성공하지 않는 상태였고, 시험은 스프링 없이 `stop()` 을 직접
불러서 영원히 못 본다.

`1024` 로 옮겼다 — 웹 서버 드레이닝 뒤, 커넥션 종료 앞. 시험은 값을 못 박는 대신
**커넥션 팩토리보다 큰가**를 잰다. 그 관계가 근거이지 상수가 근거가 아니다.

## 타임아웃이 없으면 루프가 조용히 멎는다

주기 루프에 타임아웃이 없었다. 한 판이 안 끝나면 다음 지연이 시작되지 않는데,
오류가 아니라 무응답이라 로그도 안 나온다. 그동안 이 노드는 하트비트를 못 쓰면서
요청은 계속 받는다 — 리더가 분모에서 뺀 뒤에도 통과를 만든다.

## 어떻게 검증했는가

되돌려서 죽는 것을 확인했다.

| 되돌린 것 | 죽는 시험 |
|---|---|
| 인자 없는 `start()` 를 비움 | 인자_없는_start_도_루프를_띄운다 |
| `isRunning()` 을 항상 거짓으로 | 셋 |
| phase 를 0 이하로 | 커넥션이_닫히기_전에_멈추는_단계다 |
| 루프 타임아웃 제거 | 한_판이_안_끝나도_다음_판이_돈다 |
| `HSET` → `HSETNX` | 하트비트는_매번_갱신된다 |
| 임계를 상수로 고정 / 경계를 `>=` 로 | 임계와_같은_나이는_살고_한_칸_넘으면_죽는다 |
| 미래 시각 가드 제거 | 미래_시각은_죽은_것으로_본다 |

**1970년 값으로는 임계를 못 잰다.** 56년 낡은 값은 임계가 30이든 30억이든 결과가
같아서, 그 시험은 "나이 판정이 있는가" 까지만 재고 임계 자체는 못 잰다. 서버
시각을 받아 경계 양쪽을 박으니 그제서야 죽는다.

## 고려했으나 버린 것

- **레지스트리를 없애고 스크립트 반환값을 그대로 쓴다.** 집계값 비대칭과 관측
  실패 시 유지를 둘 곳이 없어진다 — 그 둘이 이 클래스가 하는 전부다.
- **자바 쪽 판정을 남기되 서버 시각을 같이 받아 온다.** 스크립트가 항목별 시각을
  내보내야 하고, 노드 수만큼 데이터가 늘며, 여전히 임계가 둘이다.
- **phase 를 상수로 시험한다.** 값이 아니라 **관계**가 근거다. 상수를 박으면
  커넥션 팩토리 쪽이 바뀌어도 시험이 조용하다.

## 확신이 낮은 부분 · 남은 위험

**레지스트리와 루프를 잇는 배선이 아직 없다.** 루프는 관측한 수를 `IntConsumer`
로 흘리고 레지스트리는 그걸 받을 모양이지만, 스프링 빈으로 묶는 설정이 없다.
다음 태스크에서 잇는다 — 그때까지 두 클래스는 자기 시험 밖에서 안 쓰인다.

**`countFresh` 를 리더만 부르는 것은 강제하지 않는다.** 모든 노드가 부르면 각자
다른 순간의 분모를 써서 총합이 어긋난다. 리더 배선에서 지켜야 한다.

**국소 고장 노드의 상한이 없다.** 커넥션이 국소로 고장 난 노드는 로테이션에
남으면서 분모에서는 빠진다 — 계획서가 "마지막 자기 몫으로 묶는다" 는 제약을 적어
두었지만 코드는 fail-open 상한과 함께 나온다.

**회복 시나리오가 카오스 하네스에 없다.** 위에 적은 2.9배 버스트를 실제로
재현하는 시나리오가 없다. 램프다운으로 막았다고 보지만 실측은 아니다.
