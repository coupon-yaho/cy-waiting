# 두 갱신이 서로를 필요로 했다

## 무엇을 했나

뮤테이션 플러그인과 빌드 도구를 함께 올렸다.

## 왜 따로 못 가나

**빌드 도구를 먼저 올리면** 옛 플러그인이 사라진 API 를 불러 아예 안 뜬다.

```
Failed to apply plugin: unknown property 'baseDir' for extension 'reporting'
```

**플러그인을 먼저 올리면** 시험 런처 판이 갈려 테스트가 통째로 안 뜬다.
그건 앞선 수정이 이미 막았다.

즉 순서가 있다 — 런처 고정 → 플러그인 → 빌드 도구. 가운데를 빼면 깨진다.

## 재실행으로는 못 찾았다

CI 로그에는 "테스트 실패" 와 "빌드 실패" 한 줄씩뿐이었다. 그걸 보고 재실행만
반복했고, 그때마다 같은 자리에서 죽었다.

**합쳐서 로컬에서 돌리고 나서야 보였다.** 하나는 플러그인 적용 실패, 하나는
실행기 오류로 시험 이름이 아예 안 남는 종류였다.

로그가 원인을 안 알려 줄 때는 재실행이 아니라 재현이 필요하다.

## 얻은 것

비호환 경고가 사라졌다. 옛 판에서는 매 빌드마다 떴다.

```
Deprecated Gradle features were used in this build,
making it incompatible with Gradle 9.0
```

경고가 상시로 떠 있으면 아무도 안 읽는다. 그 상태로 다음 갱신을 맞으면 무엇이
새로 깨졌는지 가릴 수 없다.

## 어떻게 검증했는가

| 조합 | 결과 |
|---|---|
| 빌드 도구만 | 플러그인 적용 실패 |
| 플러그인만 (런처 고정 전) | 실행기 오류 — 시험 이름 안 남음 |
| 플러그인만 (런처 고정 후) | 전체 게이트 통과 |
| 둘 다 (런처 고정 후) | 전체 게이트 통과, 비호환 경고 없음 |

## 남은 것

**설정 캐시를 안 켰다.** 빌드 도구가 권하지만 이번 범위 밖이다. 켜면 빌드가
빨라지는 대신 스크립트의 부수 효과가 드러나므로 따로 볼 자리다.
