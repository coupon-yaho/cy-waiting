# 리뷰를 부를 때만 돌리고 두 번째 눈을 붙인다

## 무엇을

CodeRabbit 의 자동 리뷰를 끄고 `@coderabbitai review` 로 부를 때만 돌게 했습니다.
그리고 Qodo Merge 를 두 번째 리뷰 도구로 붙였습니다. 둘 다 자동으로 돌지 않습니다.

## 왜 (근거)

**리뷰가 병목이 되었습니다.** 무료 플랜은 시간당 리뷰 한 건인데, PR 을 열 때마다
자동으로 소모됩니다. 그러면 정작 지적을 반영하고 다시 볼 때 쓸 몫이 없습니다.
반영한 뒤에 부르면 같은 사용량으로 더 많이 봅니다.

**병목이 규범을 무너뜨립니다.** 리뷰를 못 받은 PR 이 쌓이면 결국 리뷰 없이
병합하려는 압력이 생깁니다. 실제로 그렇게 병합한 적이 있고, 그 뒤 리뷰가 차단
사항을 여러 건 냈습니다. 도구의 사용량 문제가 코드 품질 문제로 번진 것입니다.

**두 번째 눈이 필요합니다.** 한 도구에 의존하면 그 도구가 못 보는 것이 그대로
지나갑니다. Qodo 는 같은 규칙을 다른 각도로 봅니다.

**규칙을 설정에 복사하지 않습니다.** 두 도구 모두 `ai/rules/` 를 가리킬 뿐입니다.
사본이 생기는 순간 둘이 갈라지고, 그때부터 아무도 믿지 않습니다.

## 고려했으나 택하지 않은 것

**Qodo 도 자동으로 돌리는 것.** 도구를 늘려 병목을 푸는 방향입니다. 그런데 그러면
같은 문제가 두 배로 커질 뿐입니다 — 자동 리뷰는 언제 쓸지를 도구가 정하고, 사람은
그것을 못 막습니다. 둘 다 부를 때만 돌게 두는 편이 사용량을 사람이 쥡니다.

**기능 브랜치에 워크플로를 두는 것.** 처음에 그렇게 했는데 **동작하지 않습니다.**
`issue_comment` 로 도는 워크플로는 GitHub 이 항상 기본 브랜치의 것을 씁니다.
코멘트를 달아도 아무 일이 안 일어나고, 그 사실이 어디에도 안 드러납니다 — 리뷰를
받았다고 착각하기 딱 좋은 상태입니다.

## 리뷰가 잡은 것

**아무나 우리 키를 태울 수 있었습니다.** 공개 저장소라 누구든 PR 에 코멘트를 달 수
있고, 그 한 줄이 곧 우리 사용량입니다. 게다가 그 실행에는 PR 에 쓸 권한이 붙어
있습니다. 저장소에 쓸 권한이 있는 사람만 부를 수 있게 좁혔습니다.

**중복 호출을 막는다고 적고 안 막고 있었습니다.** `cancel-in-progress: false` 는
줄만 세울 뿐 둘 다 돌립니다. 같은 PR 에 두 번 부르면 사용량을 두 배로 쓰는데,
그것이 바로 이 설정이 막겠다고 한 것입니다.

**규칙을 가리킨다고 적고 안 가리키고 있었습니다.** `ai/rules/` 를 언급한 것은 TOML
주석뿐인데, 주석은 프롬프트에 안 들어갑니다. 실제로 전달되는 것은 손으로 추린 일부라
거기 없는 규칙은 확인될 수 없었습니다. 규칙 파일의 위치를 표로 넣고 "여기 적힌
것만으로 판정하지 말라" 고 명시했습니다.

## 확신이 낮은 부분 / 남은 위험

- **`secrets.OPENAI_KEY` 가 아직 없습니다.** 등록 전까지 Qodo 워크플로는 실패합니다.
  조용히 넘어가지 않게 둔 것은 의도입니다 — 통과하면 리뷰를 받은 것으로 오해합니다.
- **자동 리뷰를 끄면 부르는 것을 잊을 수 있습니다.** 지금은 사람이 기억해야 하고,
  기계가 막아 주지 않습니다. PR 을 열 때 리뷰 요청까지 하나로 묶는 절차가 필요합니다.
- Qodo 의 지적 품질을 아직 못 봤습니다. 키가 붙고 몇 번 돌려 본 뒤에야 두 도구를
  어떻게 나눌지 정할 수 있습니다.
- `.coderabbit.yaml` 의 거르는 조건들은 껐어도 그대로 두었습니다. 다시 켤 때 무엇을
  걸러야 하는지가 거기 남아 있어야 하고, 지우면 그 판단을 처음부터 다시 해야 합니다.

## 어떻게 검증했는가

두 설정 파일이 파싱되는지 확인했고, 워크플로 셸 검사와 문서 링크 검사를
통과했습니다. 코드는 바뀌지 않았습니다.

**동작 확인은 못 했습니다.** 키가 없어 Qodo 를 실제로 돌려 보지 못했고, 자동 리뷰가
꺼진 것도 다음 PR 을 열어 봐야 확인됩니다.

## 다음 사람이 알아야 할 것

**`issue_comment` 워크플로는 기본 브랜치에 있어야 돕니다.** 기능 브랜치에 두고
"왜 안 되지" 를 한참 봤습니다.

**리뷰를 안 받고 병합하지 않습니다.** 사용량 제한은 기다릴 이유이지 건너뛸 이유가
아닙니다. 기다리는 동안 리뷰와 무관한 티켓을 진행하면 됩니다.
