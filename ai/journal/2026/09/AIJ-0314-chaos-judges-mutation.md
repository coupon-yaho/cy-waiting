# 카오스 판정기를 뮤테이션 범위에 넣었다

## 무엇을

뮤테이션 대상이 main 소스셋의 네 패키지뿐이라, 픽스처 소스셋의 판정기(`RecoveryCriteria`,
`BackendRpsRecorder`)는 압력이 0 이었다. 모든 시나리오의 합격선이 여기서 나오는데 한계 부등호를 한 칸
옮겨도 초록이었다.

## 실측

판정기 두 클래스만 대상으로 돌렸다. 111 중 97 이 죽었다(87%). 살아남은 것은 거의 전부 경계 변화였다 —
재고 0, 한계와 같은 복귀 시간, 정상 구간 0, 봉우리 0, 보낸 수 0, 도착 0, 허용 오차와 같은 드리프트,
구간 끝 초. 오차 백분율 문구의 곱셈과 앞값 0 갈래는 시험이 아예 안 닿았다.

## 고친 것

- 살아남은 자리마다 경계값에서 결과가 갈리는 시험을 붙였다. "못 쟀다" 와 "하나도 안 받았다" 처럼 같은 위반이라도
  문구가 다른 갈래는 문구로 가른다
- 픽스처 소스셋을 뮤테이션에 같이 넘기고 판정기 클래스만 짚었다. 패키지째 넣으면 대상 시험도 패키지째
  끌려와 컨테이너를 띄우는 시나리오가 들어온다. 대상 시험의 기본값이 대상 클래스 패턴이라 판정기 시험 둘만 붙는다

## 어떻게 검증했나

- 판정기만: 111 중 110 (99%). 남은 하나는 표집의 `delta <= 0` 을 `< 0` 으로 바꾼 것으로, 0 을 더할 뿐이라 결과가
  같은 등가 뮤턴트다
- 상시 설정으로 전체를 돌려 임계와 시나리오 유입을 확인했다 (결과는 PR 에 적는다)
