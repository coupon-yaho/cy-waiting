# cy-waiting — 적응형 대기열 게이트웨이

Spring WebFlux 기반 대기열 게이트웨이. 대규모 선착순 쿠폰 발급에서
**뒷단 가용량에 맞춰 유입을 조절**하고, 몰리지 않는 쿠폰은 대기열 없이 통과시킨다.

```
클라이언트 ──▶ 게이트웨이 N대 ──▶ 쿠폰 서비스 N대 ──▶ MySQL / Redis / Kafka
                판정 · 대기열          발급 · 재고 차감
```

발급 계층은 별도 저장소(`cy-be`)에 있다. 게이트웨이는 **입장만** 소유하고
발급도 재고 차감도 하지 않는다.

---

## 무엇을 푸는가

| | 요구 |
|---|---|
| **R1** | 몰리지 않는 쿠폰은 대기열 없이 즉시 통과, 몰리는 쿠폰만 대기열 |
| **R2** | 뒷단 N대의 가용량 비율대로 분산 |
| **R3** | 매진 쿠폰은 Redis·백엔드를 거치지 않고 게이트웨이가 종결 |
| **R4** | 피크 100K RPS · 동시 대기 20,000 |
| **R5** | **장애 진입·유지·회복 전 구간에서 정합성과 공정성 유지** |
| **R6** | 대기 순위·ETA 제공. 근사 허용, 단조성은 타협 불가 |

R5 가 무게중심이다. 장애 중 동작만이 아니라 **회복 전이**까지 카오스로 판정한다.

---

## 절대 어기지 않는 것

| # | 불변식 | 깨지면 |
|---|---|---|
| 1 | **요청 경로에서 Redis 를 치지 않는다** | 게이트웨이의 존재 이유가 사라진다 |
| 2 | **순번 역행 0** | 사용자가 뒤로 밀린다. 선착순의 신뢰가 깨진다 |
| 3 | **줄 선 사람을 추월시키지 않는다** | 장애 중에도. 공정성은 가용성과 맞바꿀 수 없다 |

3번이 함정이다. **"상태를 모른다"는 것이 추월을 정당화하지 않는다.**

## 진행 상황

**Phase 9 (Routing) — v0.6.0. 검증까지 끝냈고 게이트 하나가 미달이다.** 제로베이스 재작성이며,
판정 도메인부터 큐 생명주기까지가 자동 판정 게이트를 넘겨 닫혔다.

유입 비율·재분배·복귀·롤링 배포는 실측으로 넘겼고, **인스턴스 종료 시 유출**만 남았다 —
서킷이 뒷단 전체에 하나뿐이라 한 대가 죽으면 멀쩡한 나머지로 갈 요청까지 막힌다.

| 페이즈 | 무엇 | 상태 |
|---|---|---|
| 1~7 | 검증 기반 · 입장 판정 · Redis · 제어 평면 · 요청 경로 · 보호 · 큐 생명주기 | 닫힘 |
| 8 | 장애 회복력 (R5) | **부분 충족으로 닫힘** — 게이트 표에 무엇이 남았는지 있다 |
| 9 | 가용량 기반 라우팅 (R2) | **구현 완료 · 검증 남음** — 만든 것과 잰 것을 게이트 표가 가른다 |
| 10 | 규모 확장 | 제목 + 근거 · 착수 측정만 |

각 페이즈는 **자동 판정 가능한 수치**를 넘겨야 닫힌다.
전체 계획은 [`plan/README.md`](plan/README.md).

## 개발

```bash
./gradlew build          # JDK 21 이 없어도 된다 — foojay resolver 가 받아온다
./gradlew test
```

`feature/CY-<번호>-<슬러그>`, PR 은 squash 하지 않는다.
