# 픽스처가 프로덕션이 거절하는 형식으로 쓰고 있었다

## 무엇을

가용량 보고 픽스처의 값 형식을 프로덕션 파서에 맞췄다.

## 왜

C7 을 만들며 크레딧이 안 올라가는 것을 추적하다 드러났다. 픽스처는 값과 시각을
콜론으로 이어 썼는데 **프로덕션 포트는 JSON 을 읽는다.**

```
가용량 보고를 걸렀다 — c7-be-b: Unexpected character (':' (code 58))
가용량을 못 읽는다 — 직전 값으로 배분한다
```

포트가 전부 걸러 크레딧이 하한에 박혔다.

## 왜 아무도 못 잡았나

픽스처의 자기 시험이 **자기가 쓴 것을 자기가 읽는다.** 형식이 무엇이든 통과한다.
실제 포트에 태우는 시험이 없었다.

그래서 이 픽스처 위에 세운 시험들이 전부 **뒷단이 거절하는 상태**를 재고 있었다.
"통과가 근거가 못 된다" 는 이 저장소가 여러 번 만난 형태인데, 이번에는 픽스처
자신이 그 자리였다.

## 남긴 것

계약을 못 박는 시험이 없다. 픽스처가 쓴 값을 실제 포트로 읽어 같은 값이 나오는지
보면 형식이 갈리는 순간 그 자리에서 잡힌다. 지금은 사람이 두 파일을 나란히 놓고
읽어야만 안다.
