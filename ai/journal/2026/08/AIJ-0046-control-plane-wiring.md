# 안 엮이면 아무것도 안 돈다

## 무엇을 만들었나

레디스 어댑터 둘과 스프링 배선, 그리고 시간 예산 설정.

## 조각이 다 초록인데 사이가 비어 있었다

리더 판정도 배분 루프도 각자 시험을 통과하는데, 둘을 잇는 것이 없으면 배분이
영영 안 돈다. **그 상태로도 프로세스는 멀쩡히 뜬다.** 앞선 티켓의 저널에 남긴
위험이 그것이었고, 여기서 닫았다.

## 위치로 짝지으면 조용히 틀린다

수요 수집이 대기 수와 재고를 **다른 명령**으로 읽는다. 처음엔 둘 다 목록으로
받아 위치로 맞췄는데, 응답이 한 칸만 밀리면 어떤 쿠폰의 대기가 다른 쿠폰의
재고와 붙는다. 그 조합은 도메인이 안 막으므로 **아무 신호 없이 틀린 배분**이
나간다.

되돌리기에서 이게 드러났다. 순서를 뒤섞는 뮤턴트가 살아남았는데, 쿠폰이 둘뿐이라
운 좋게 순서가 유지된 것이었다. **더 많은 쿠폰으로 시험을 늘리는 대신 짝짓는
방식을 바꿨다** — 쿠폰 이름으로 맞추면 순서가 어긋날 자리가 없다.

시험으로 막을 수 있는 결함과 설계로 없앨 수 있는 결함이 있으면 뒤쪽이 낫다.

## 발행은 통째로 갈아 끼운다

남기면 끝난 쿠폰이 스냅샷에 영영 남아, 각 노드가 없는 쿠폰을 계속 판정한다.

## 어긋나면 안 뜨게 한다

연장 예산은 어긋나도 예외가 안 난다. 조용히 리더가 없어지고, 배분이 멎고,
5초 뒤 낡음이 뜨는데 그걸로는 거절을 못 하니 그대로 통과가 나간다. 그래서
기동에서 막는다.

- 회복하는 판까지 리스 안에 들어와야 한다 — `4 × (시도 + 지연) + 시도 ≤ lease`
- 리스는 틱보다 길어야 한다. 판을 도는 중에 리더십을 잃으면 다음 리더가 같은
  판을 다시 돌아 두 배가 나간다
- 신선도는 틱보다 길어야 한다. 짧으면 한 틱만 밀려도 전 인스턴스가 낡음이 되어
  하한으로 떨어지고, 아무 문제 없는 쿠폰까지 줄을 세운다

## 배분 루프는 전용 스레드에서 돈다

공용 스케줄러로 가면 요청 처리 뒤에 줄을 선다. **트래픽이 몰릴 때 정확히
그만큼 틱이 밀린다** — 가장 필요할 때 가장 늦는다.

## 어떻게 검증했는가

되돌려서 죽는 것을 확인했다.

| 되돌린 것 | 죽는 시험 |
|---|---|
| 발행에 옛 필드 남김 | 발행은_통째로_갈아_끼운다 |
| 없는 재고를 0 으로 | 재고를_따로_읽는다 |
| 들인 인원 대신 임계 | 적용하면_임계가_올라간다 |
| 회복 판을 예산에서 뺌 | 둘 |
| 시도 수를 3 으로 | 둘 |
| 예산 경계 느슨하게 | 둘 |
| 리스와 틱 비교 제거 | 리스는_틱보다_길어야_한다 |
| 신선도 검사 제거 | 신선도는_틱보다_길어야_한다 |
| 인스턴스 상한 검증 제거 | 가용량_값이_잘못되면_안_뜬다 |
| 샤드·첫 판 지연 검증 제거 | 스케줄러_값이_잘못되면_안_뜬다 |

**인스턴스 상한 검증은 처음에 안 물렸다.** 0 이면 어떤 보고도 0 으로 잘려
크레딧이 영영 안 나가는데, 그걸 재는 시험이 없었다.

## 고려했으나 버린 것

- **수요 수집을 위치로 짝짓기.** 위 참조. 시험으로 막느니 자리를 없앤다.
- **가용량 값을 상수로.** 운영에서 바꿀 값인데 상수면 배포가 필요하다. 다만
  아직 설정 파일에서 안 읽고 기본값만 쓴다 — 다음이다.
- **배분 루프를 공용 스케줄러에.** 몰릴 때 밀린다.

## 연장을 아무도 안 부르고 있었다

리더 판정 클래스는 연장을 **제공만** 하고, 그걸 주기적으로 부르는 곳이 없었다.
그대로 뜨면 리스가 만료돼 리더가 조용히 사라진다 — 배분은 멎는데 예외도 로그도
안 난다.

배분 틱에 얹지 않고 따로 돈다. 주기가 다르기 때문이다. 얹으면 연장이 배분만큼
드물어져 리스를 못 지킨다.

## 종료는 순서가 전부다

**연장을 먼저 멈춘다.** 안 그러면 방금 비운 락을 죽는 노드가 다시 잡고, 놓은
이득이 통째로 사라진다.

**커넥션이 닫히기 전에 놓는다.** 뒤면 매번 실패한다. 웹 서버가 빠진 뒤,
커넥션 팩토리가 닫히기 전 — 그 사이가 유일한 창이다. 단계를 상수로 못박지 않고
**그 관계를** 시험이 지킨다.

**해제가 종료를 붙들면 안 된다.** 못 놓아도 리스 만료로 풀리지만, 붙들면
오케스트레이터가 강제로 끊고 그때는 진행 중인 요청까지 함께 끊긴다.

앞선 티켓에서 미구현으로 남겨 둔 종료 시 락 해제가 여기서 닫혔다
([AIJ-0041](AIJ-0041-leadership.md) 정정 참조).

## 리뷰가 잡은 것들

**빈을 만들 때 레디스를 읽었다.** 평활화 이월을 그렇게 붙였더니 **레디스가 안
뜨면 앱이 통째로 안 뜬다.** 이월은 있으면 좋은 것이지 기동의 전제가 아니다.
첫 판에서 받게 옮겼고, 한 번만 받는다 — 매 판 받으면 방금 쓴 값을 되읽어
평활화가 아무 일도 안 하게 된다.

**샤드를 여럿 받으면서 적용은 0번에만 나갔다.** 나머지 샤드의 줄은 영원히 안
빠지는데 아무 오류도 안 난다. 산문으로 지킬 일이 아니라서 기동에서 하나로 막았다.

**활성 목록이 밖에서 쓰는 키다.** 키로 못 쓰는 멤버 하나가 판을 죽이면 멀쩡한
쿠폰 전부의 배분이 멎고, 사람이 목록을 고치기 전에는 안 풀린다. 걸러 내되
걸러 냈다는 사실을 남긴다.

**리더십을 판 시작에서만 봤다.** 리스가 10ms 남은 상태로 시작한 판이 한 틱을
꽉 채워 돌고, 그 사이 다음 리더가 자기 판을 돈다. 쓰기 직전에 다시 묻는다 —
비용이 메모리 읽기 하나라 안 물어볼 이유가 없다.

**로그가 폭포였다.** 초당 한 판에 쿠폰마다 찍으면 단절 한 번에 수만 줄이다.
같은 억제 장치가 이미 세 곳에 복사돼 있어 공용으로 뽑았다.

## 확신이 낮은 부분 · 남은 위험

**설정 파일에서 아직 안 읽는다.** 기본값만 쓴다. 값을 바꾸려면 코드를 고쳐야
하는데, 검증은 이미 자리를 잡았으니 읽는 쪽만 붙이면 된다.

**틱 지연을 재기만 하고 버린다.** 지표 배선이 없어서다 — CY-344.

**히스테리시스를 아직 안 태웠다** — CY-324 의 결정이 먼저다.
