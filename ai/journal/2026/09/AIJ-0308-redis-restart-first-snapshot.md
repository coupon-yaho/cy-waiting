# 첫 스냅샷 5초와 갱신 루프 정지 0 을 C1b 로 잰다

## 무엇을

계획서 C1 은 회복 판정으로 "첫 스냅샷까지 5초" 를, 유지 판정으로 "갱신 루프 정지 0" 을 요구하는데 둘 다
재는 판정이 없었다 (CY-816, CY-828).

## 티켓보다 앞선 전제

CY-816 은 관측 지점을 먼저 정하라고 적었다. 파 보니 **C1 에서는 원리상 못 잰다.** C1 은 재료를 스텁으로
받아 레디스를 끊어도 받아오기가 안 멎고, 고정 시계라 받아온 나이와 틱 나이가 늘 0 이다. 그래서 따로
세웠다. 실제 받아오기·실시계·스케줄러를 켜고 레디스 프로세스를 죽였다 살린다.

## 처음에 빨갛던 이유

레디스가 살아난 뒤 20초가 지나도 못 받았다. 제품 결함으로 읽기 전에 갱신 루프를 봤다. **쿠폰이 하나도
없는 스냅샷은 안 받는다** — 빈 해시는 흔한 상태라 들고 있던 것을 유지한다. 픽스처가 영속성 없이 띄워
재기동에 활성 쿠폰 목록이 통째로 사라졌고, 새로 발행된 스냅샷이 비어 거절됐다. 운영 레디스는 영속성을
켜므로 영속 픽스처로 바꿨다.

## 무엇을 판정하나

- 유지: 받아오기가 정말 멎었다(나이 3초 초과) — 안 멎으면 아래가 아무것도 안 잰다
- 유지: 발행된 스냅샷을 안 버렸다
- 유지: 4초 동안 루프가 돈 뒤 나이가 2.5초를 안 넘는다. 실측 최대 0.9초
- 회복: 레디스가 준비된 순간부터 발행된 스냅샷을 다시 받기까지 5초 이내. 실측 1.5초

## 어떻게 검증했나

- 두 한계를 1ms 로 줄이는 프로브로 각각 빨개지는 것을 보고 되돌렸다

## 남은 것

- 영속성이 없는 레디스가 재기동하면 갱신이 끝내 안 돌아온다. 쿠폰을 다시 등록해야 풀린다. 되감긴 데이터를
  잡는 신호는 CY-856 이다
