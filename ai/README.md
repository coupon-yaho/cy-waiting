# ai/ — AI 작업 규범

도구에 종속되지 않는 **지식**을 담는다. Claude Code 배선(`.claude/`)과 분리되어 있어
도구가 바뀌어도 그대로 남고, 사람도 읽는다.

---

## 구조

| 경로 | 내용 | 갱신 주기 |
|---|---|---|
| `rules/` | 코딩·설계 규칙 | 합의가 바뀔 때 |
| `journal/` | **AI 작업 로그** — 무엇을 왜 했는가 | 작업할 때마다 |

---

## ADR 과 journal 의 차이

`plan/90-decisions.md` 는 되돌리려면 설계 회의가 필요한 결정,
`ai/journal/` 은 커밋 하나로 되돌아가는 판단이다.
작업 중 ADR 급이 나오면 journal 에 적고 승격하면서 `promoted-to:` 를 남긴다.

---

## 규칙을 고칠 때

1. 규칙 변경도 **커밋으로** 남긴다 — `docs(rules): ...`
2. 변경 이유를 journal에 기록한다. 규칙은 결과지 근거가 아니다
3. 기존 코드가 새 규칙을 어기면 **일괄 수정하지 말고** 별도 태스크로 분리한다
   — 규칙 변경과 코드 변경이 한 커밋에 섞이면 리뷰가 불가능해진다

---

## 규칙이 현실과 어긋날 때

**규칙을 조용히 어기지 않는다.** 둘 중 하나를 한다.

| 상황 | 조치 |
|---|---|
| 이번 한 번만 예외 | 코드에 `RULE-EXCEPTION(<규칙 ID>): <이유>` 주석 + journal 기록 |
| 규칙 자체가 틀림 | 규칙을 고치는 PR을 별도로 낸다 |

### 예외 주석을 다는 위치

훅은 **위반한 줄 자체 또는 바로 위 3줄**에서만 예외 주석을 찾는다.
문장 바로 위에 달아도, 메서드 시그니처 위에 달아도 인정된다.

```java
// RULE-EXCEPTION(RX-1): 종료 경로. 타임아웃 1초를 걸어 종료가 지연되지 않는다
@PreDestroy
public void stop() {
    redis.remove(key).timeout(Duration.ofSeconds(1)).block();
}
```

파일 맨 위에 몰아서 달면 인정되지 않는다 — **무엇에 대한 예외인지 사라지기 때문**이다.

**이유를 반드시 적는다.** 이유 없는 예외 주석은 규칙을 끈 것과 같다.

### 예외가 쌓이면 규칙을 의심한다

**같은 규칙에 예외가 3건 이상 쌓이면 그 규칙을 재검토한다** —
반복적으로 어기게 되는 규칙은 대개 규칙 쪽이 틀렸다.

```bash
rg -o 'RULE-EXCEPTION\([A-Z]+-[0-9]+\)' src/ | sort | uniq -c | sort -rn
```
