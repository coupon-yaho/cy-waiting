# 임계는 개수가 아니라 자리다

## 무엇을 만들었나

수요 수집과 배분 적용. 크레딧 산출은 도메인에 이미 있고, 여기서는 그 앞뒤다.

## 두 값을 다른 시점에 재면 쿠폰이 사라진다

크레딧을 산출한 뒤 대기 수를 다시 읽으면 그 사이에 사람이 빠진다. 그러면 도메인이
막는 조합이 발행되고, 코덱은 **그 쿠폰만** 떨군다. 떨어진 쿠폰은 판정에서 없는
쿠폰이니 **매진**으로 보인다. 정상 동작이 전면 차단으로 번지는 경로다.

그래서 한 번 읽은 값을 들고 끝까지 간다.

## 짧은 응답을 채우면 줄이 통째로 멈춘다

파이프라인 응답의 길이가 안 맞을 때 모자란 자리를 0 으로 채우면 대기가 0 인
쿠폰이 된다. 크레딧이 안 나가고, 줄 선 사람이 통째로 멈추는데 **아무 신호도
없다.** 판을 버리면 다음 판에 다시 시도한다.

## 임계를 개수로 세면 두 배가 들어온다

개수를 올리는 방식은 두 가지가 걸린다. 떠난 사람의 자리까지 소모하고, 리더가
겹쳐 같은 판이 두 번 적용되면 **두 배가 입장한다.**

자리(score) 를 임계로 쓰면 두 번 적용돼도 값이 같다. 펜싱 토큰을 안 쓰는 근거가
여기서 나온다.

## 세 가지를 조심해야 했다

**이미 들어온 사람은 다시 안 센다.** 앞에서부터 세면 통과한 사람 자리에 크레딧을
낭비하고, 그만큼 실제로 들어오는 사람이 준다. 현재 임계 바로 위에서부터 센다.

**크레딧이 큐보다 커도 무한대를 안 쓴다.** 무한대면 이후 도착자까지 임계 아래로
들어와 **줄을 서지 않고 통과한다.** 큐의 마지막 사람 자리로 둔다.

**임계는 뒤로 안 간다.** 들어온 사람이 큐에서 빠지면 남은 최대 자리가 임계보다
작아지는데, 그때 계산값을 그대로 쓰면 이미 통과한 사람이 다시 대기가 된다.

## 어떻게 검증했는가

되돌려서 죽는 것을 확인했다. 실물 레디스로 돌렸다.

| 되돌린 것 | 죽는 시험 |
|---|---|
| 앞에서부터 센다 | 이미_들어온_사람은_다시_안_센다 |
| 크레딧 초과에 무한대 | 셋 |
| 임계가 뒤로 갈 수 있음 | 임계는_뒤로_가지_않는다 |
| 크레딧 0 에도 진행 | 셋 |
| 인원 검증 제거 | 들일_인원이_잘못되면_거절한다 |
| `LIMIT` 오프셋 어긋남 | 다섯 |
| 빈 대상에도 조회 | 배분_대상이_없으면_아무것도_안_묻는다 |
| 대기·재고 길이 검사 제거 | 길이가_안_맞으면_판을_버린다 |
| 없는 값을 1 로 | 둘 |
| 샤드 오프셋 무시 | 샤드가_여럿이면_합쳐_센다 (어댑터로 옮겼다) |

**둘이 처음에 안 물렸다.** 응답 길이는 대기 쪽만 어긋나게 재서 재고 검사를 통째로
지워도 통과했다. 임계 되돌림은 계산값이 현재와 같은 상황을 만들어서, 막든 안 막든
같은 값이 나왔다 — 들어온 사람이 큐에서 빠져 **남은 최대가 임계보다 작아지는**
상황이라야 갈린다.

## 나중에 드러난 것 — 문서화된 함정을 그대로 밟았다

리뷰가 실물 레디스로 재현했다. **수를 문자열로 만들 때 열넷째 자리까지만 찍는
함수를 썼다.** 마이크로초 score 는 열여섯 자리라 과학 표기로 접히며 최대
100마이크로초가 반올림된다.

올림 쪽으로 접히면 그 사이 도착자가 줄을 안 서고 통과하고, 내림 쪽으로 접히면
이미 통과한 사람이 다시 대기가 된다. 불변식 셋과 넷이 동시에 깨진다.

**같은 저장소의 대기열 진입 스크립트가 이 함정을 주석으로 못박아 뒀다.** 같은
값, 같은 함수, 같은 결과. 새 스크립트만 규약을 안 따랐다.

시험이 이걸 못 본 이유가 더 중요하다 — **두 자리 수로만 쟀다.** 운영에서 절대
나오지 않는 값이라 시험은 초록인데 운영에서만 깨진다. 도달 불가한 상태를 만드는
것보다 **도달하는 값을 안 쓰는 것**이 더 위험하다.

## 고려했으나 버린 것

- **수요 수집을 Lua 로.** 쿠폰마다 슬롯이 갈려 클러스터에서 못 돈다. 잃는 것은
  진단 편의뿐이다.
- **재고를 같은 스크립트에서 읽기.** 재고 키는 샤드 무관이라 슬롯이 갈린다.
- **모르는 재고를 크게 잡기.** 재고보다 많이 통과시키게 되고, 초과 발급은
  되돌릴 수 없다. 모르는 쪽은 작게 본다.

## 확신이 낮은 부분 · 남은 위험

**아직 엮지 않았다.** 틱 루프·수요 수집·배분 적용이 따로 있고, 크레딧 산출과
평활화를 사이에 넣는 것이 다음이다.

**샤드별 대기 수를 안 들고 나온다.** 수집이 쿠폰 단위로 합쳐 버려서, 샤드마다
임계를 잡으려면 그 값이 필요하다. 샤드가 하나인 동안은 안 드러난다.

**`entering` 을 아직 아무도 안 쓴다.** 실제로 들어온 인원이라 평활화의 재료가
되는데, 지금은 돌려주기만 한다.
