# 로깅·관측 규칙 (LG)

> 프로덕션 관제는 Loki로 한다. **로그가 없으면 아무것도 볼 수 없고,
> 로그가 너무 많으면 아무것도 찾을 수 없다.** 100K RPS에서 이 둘은 종이 한 장 차이다.

---

## LG-1 · MUST · 요청당 로그를 남기지 않는다

100K RPS × 로그 한 줄 = **하루 86억 줄**. Loki가 먼저 죽고, 죽지 않아도
그 안에서 아무것도 못 찾는다.

| 목적 | 도구 |
|---|---|
| **세는 것** (판정 분포, 통과/거절 수, 지연) | **메트릭** (Micrometer → Prometheus) |
| **맥락** (왜 이 상태가 됐는가, 무엇이 바뀌었는가) | **로그** (Loki) |

```java
// 금지 — 판정마다 로그
log.info("판정 완료. couponId={}, decision={}", couponId, decision);

// 올바름 — 판정은 메트릭으로 센다
meterRegistry.counter("waiting.admission", "decision", decision.name()).increment();
```

**로그로 카운트하지 않는다.** Loki 집계는 비싸고 느리다.

---

## LG-2 · MUST · 상태 **전이**를 로깅한다 — 진입과 해제를 쌍으로

이 시스템에서 로그가 있어야 할 곳은 요청이 아니라 **전이**다.

```java
// 진입만 로깅하면 회복을 관제할 수 없다
log.warn("fail-open 진입. 마지막 배분 후 {}ms 경과", dataAge.toMillis());
...
log.info("fail-open 해제. 지속 {}ms, 그동안 통과 {}건", duration.toMillis(), passed);
```

**해제 로그에 지속 시간과 그동안의 영향을 담는다.** 장애가 걷힌 뒤
"얼마나 오래, 얼마나 크게 영향을 받았는가"를 사후에 답할 수 있어야 한다.
→ 회복 판정 RC3·RC6과 직접 연결된다.

### 이 프로젝트에서 반드시 로깅할 전이

| 사건 | 레벨 | 쌍이 되는 해제 로그 |
|---|---|---|
| 리더 획득 / 상실 | INFO | ✅ |
| 첫 스냅샷 적재 완료 | INFO | — (1회성) |
| 스냅샷 갱신 실패 → 성공 복귀 | WARN → INFO | ✅ |
| `dataStale` 진입 / 해제 | WARN → INFO | ✅ |
| fail-open 진입 / 해제 | WARN → INFO | ✅ |
| 서킷 OPEN / HALF_OPEN / CLOSED | WARN → INFO | ✅ |
| 쿠폰 `CLOSED`(매진) 전이 | INFO | — |
| 게이트웨이 수 변화 | INFO | — |
| 가용량 보고 신선도 상실 / 회복 | WARN → INFO | ✅ |
| 큐 상한 도달 / 해소 | WARN → INFO | ✅ |
| **시계 역행 감지 후 `maxscore` 점프** | **ERROR** | — |
| **틱 배분 합계가 `globalCredit` 초과** | **ERROR** | — |
| 인스턴스 수가 라우팅 가정(A7) 밖 | **WARN** | 전략 재검토 신호. 자동 전환하지 않으므로 이 로그가 유일한 알림이다 |
| 틱 지연이 임계 초과 | WARN | — |

ERROR 둘은 발생하면 제품의 기본 보증이 깨진 것이라 **6.9 의 호출 규칙이 이 둘을
증상으로 삼는다.**

**초과 발급 자체는 게이트웨이가 못 본다** — 재고는 발급 계층이 갖는다 (비목표).
그래서 게이트웨이가 관측할 수 있는 **선행 지표**(틱 배분 합계 초과)를 대신 남긴다.

## LG-3 · MUST · 반복 로그를 억제한다

장애 중에는 같은 로그가 초당 수천 번 나온다. **WARN 하나가 폭포가 된다.**

```java
// 억제기: 같은 키에 대해 최소 간격을 두고, 그 사이 발생 횟수를 함께 남긴다
suppressor.warn("snapshot-refresh-failed",
        () -> log.warn("스냅샷 갱신 실패 {}회. 마지막 갱신 후 {}ms", count, age));
```

- 최소 간격 기본 **1초**, 지속되면 지수적으로 늘린다 (최대 1분)
- **억제된 횟수를 반드시 로그에 포함**한다. 안 그러면 심각도를 알 수 없다

---

## LG-4 · MUST · Loki 라벨은 저카디널리티만

Loki는 **라벨마다 스트림을 만든다.** 고카디널리티 라벨 하나가 인덱스를 무너뜨린다.

| 라벨로 **쓴다** | 라벨로 **쓰지 않는다** (구조화 필드로) |
|---|---|
| `app`, `env`, `instance` | `couponId` |
| `level` | `memberId` |
| `logger` (패키지 수준) | `requestId`, `traceId` |
| `coupon_version` (v1/v2/v3) | `score`, `rank`, `decision` |

```java
// 금지 — 쿠폰 147개 × 인스턴스 20개 = 스트림 2,940개
MDC.put("couponId", String.valueOf(couponId));   // 라벨로 승격되는 설정일 때

// 올바름 — 구조화 필드. 검색은 되지만 인덱스를 늘리지 않는다
log.warn("큐 상한 도달. couponId={}, waiting={}, cap={}", couponId, waiting, cap);
```

라벨 추가는 **되돌리기 어렵다** — 기존 스트림이 남는다. 추가 전에 카디널리티를 계산한다.

> **아직 훅이 막지 않는다.** 라벨은 Java 코드가 아니라 Loki 어펜더 설정에서
> 정해지므로, 그 설정이 생기는 6.5.2 에서 허용 라벨 목록 검사를 함께 만든다.
> 그때까지는 사람 리뷰가 유일한 방어다.

---

## LG-5 · MUST · 리액티브에서 MDC를 쓰지 않는다

`MDC`와 `ThreadLocal`은 리액티브 체인에서 스레드를 넘나들며 **조용히 깨진다** —
빈 값이 되거나 **다른 요청의 값이 섞인다.** 후자가 더 위험하다.

상관관계 정보는 **Reactor Context** 또는 명시적 인자로 나른다.
Micrometer Tracing을 쓰면 `traceId`/`spanId`가 Context로 전파된다.

---

## LG-6 · MUST · 개인정보와 비밀을 로그에 남기지 않는다

| 금지 | 대신 |
|---|---|
| `memberId` 원본 | 해시 앞 8자 또는 마스킹 |
| 입장 토큰 | 절대 금지 (서명 일부도 금지) |
| HMAC 시크릿 | 절대 금지 |
| 요청 바디 | 애초에 읽지 않는다 (RX-7) |
| 인증 헤더 | 절대 금지 |

로그는 보존 기간이 길고 접근 권한이 넓다. **한 번 새면 회수할 수 없다.**

---

## LG-7 · MUST · 레벨의 의미를 지킨다

| 레벨 | 의미 | 프로덕션 |
|---|---|---|
| `ERROR` | **사람이 개입해야 한다** | 켬 |
| `WARN` | 자동 복구되지만 **지속되면 문제** | 켬 |
| `INFO` | 상태 전이. 저빈도여야 한다 | 켬 |
| `DEBUG` | 개발·조사용 | **끔** |
| `TRACE` | 쓰지 않는다 | 끔 |

**ERROR를 남발하지 않는다.** 자동 복구되는 것은 WARN이다.
ERROR가 잦으면 알람이 무시되고, 그때 진짜 ERROR가 묻힌다.

**레벨이 곧 페이지 대상은 아니다.** 호출·티켓 규칙은
[plan/06-protection.md](../../plan/06-protection.md) 6.9 가 정하고, 그건 **증상**
(초과 배분·순위 역행·SLO 소진율)에 건다. 원인마다 페이지하면 장애 하나가 열 개를
울린다 (P-2). ERROR 는 조사 진입점이지 페이지 트리거가 아니다.

반대로 **자동 복구되지 않는 것을 WARN으로 낮추지 않는다.**

## LG-8 · SHOULD · 로그 메시지에 판단 근거를 담는다

```java
// 약함 — 무엇을 봐야 할지 모른다
log.warn("배분 틱이 밀렸습니다");

// 강함 — 다음 행동이 정해진다
log.warn("배분 틱이 {}ms 밀렸습니다. 스케줄러 분리를 검토하세요.", lag.toMillis());
```

**로그를 읽는 사람이 무엇을 해야 하는지**가 드러나야 한다.
값 없는 로그는 노이즈다.

---

## LG-9 · SHOULD · 로그 메시지는 한글, 필드명은 영문

운영자가 읽는다. 필드는 `couponId=`, `waiting=` 처럼 영문 키=값으로 붙여
Loki에서 파싱 가능하게 한다.

---

## LG-10 · SHOULD · 예외는 마지막에 한 번만 로깅한다

같은 예외를 계층마다 로깅하면 하나의 사고가 다섯 줄이 된다.
**처리하는 곳에서 한 번만** 남기고, 중간 계층은 맥락을 덧붙여 다시 던진다.

```java
// 중간 계층 — 로깅하지 않고 맥락만 더한다
.onErrorMap(e -> new QueueAccessException(couponId, e))

// 최종 처리 지점 — 여기서 한 번만
.onErrorResume(e -> { log.warn("큐 등록 실패. couponId={}", couponId, e); ... })
```

예외 객체는 **마지막 인자로** 넘긴다 (`log.warn(msg, arg1, ex)`) — 그래야
스택트레이스가 붙는다. 문자열 연결로 넣으면 스택이 사라진다.

---

## LG-11 · SHOULD · 관제 대시보드와 로그를 함께 설계한다

로그를 추가할 때 **어느 패널에서 볼 것인지**를 같이 정한다.
볼 곳이 없는 로그는 남기지 않는다.

| 패널 | 로그·지표 |
|---|---|
| 판정 분포 | `waiting.admission.decision` (메트릭) |
| 장애 전이 타임라인 | LG-2의 전이 로그 (Loki) |
| 회복 소요 시간 | 전이 쌍의 간격 (Loki 파생) |
| 백엔드 유입 RPS | 메트릭 |
| ERROR 발생 | 즉시 알람 |
