# 훅·문서 재검토 — 훅에서 결함 6건, 계획서에서 죽은 분기 1건

## 무엇을

작성한 훅 5개와 문서 전체를 실제 입력으로 재검토했다.
훅에서 **6건**, 계획서에서 **1건**, 배선에서 **1건**의 결함을 찾아 고쳤다.
자기검증 케이스를 24개에서 46개로 늘리고 발견한 결함마다 회귀 케이스를 붙였다.

## 왜 (근거)

훅이 통과시킨다고 규칙이 지켜지는 것이 아니다. **검사가 실제로 위반을 잡는지,
그리고 정상 코드를 잘못 막지 않는지**를 실제 입력으로 확인해야 한다.

### 훅 결함

| # | 결함 | 영향 |
|---|---|---|
| 1 | `git -c user.name=X commit` 을 탐지하지 못함 | **이 저장소의 모든 커밋이 검사를 우회했다.** `"git commit"` 부분 문자열 매칭이 옵션 삽입에 빗나갔다 |
| 2 | `redis.call('SET', KEYS[4], '1', ...)` 를 위반으로 오탐 | 정상 Lua 를 전부 차단. 셋째 인자 이후의 리터럴은 값이지 키가 아닌데 구분하지 못했다 |
| 3 | 줄 끝 주석 안의 FQDN 을 위반으로 오탐 | `// java.util.List 대신 배열` 같은 주석이 차단됨 |
| 4 | `private static Logger log = ...` 를 메서드로 오탐 | 필드와 메서드를 구분하지 못했다 |
| 5 | 수식어 없는 중첩 클래스(`class Inner`)를 놓침 | 가장 흔한 형태를 못 잡았다 |
| 6 | 한 줄 javadoc(`/** x */`) 이후 검사가 멈춤 | 여는 패턴만 보고 같은 줄의 닫힘을 못 봐 이후 전부 무검사 |

1번이 가장 심각하다. **검사를 통과시키는 훅은 없는 훅보다 나쁘다** —
지켜지고 있다고 착각하게 만들기 때문이다.

2~6번은 오탐과 미탐이 섞여 있는데, **오탐이 더 위험하다.** 정상 코드를 막는 훅은
곧 우회되고, 우회된 훅은 그때부터 아무것도 막지 못한다.

### 계획서 결함

`plan/02-domain-core.md` 의 판정 순서에서 **큐 상한 검사가 도달 불가능**했다
(당시 4.5절, 문서 재작성 후 3.5절).

```
7. runtime != IDLE          → ENQUEUE_BACKLOG
8. waiting >= queueCapacity → REJECT_QUEUE_FULL   ← 영원히 도달하지 않는다
```

`waiting >= queueCapacity` 이려면 `waiting > 0` 이고, 그러면 `runtime != IDLE` 이라
7번에서 먼저 반환된다. 큐로 보내는 판정 **전체보다 앞**으로 옮겨야 상한이 걸린다.

### 배선 결함

`guard-paths.sh` 를 Bash 명령까지 검사하도록 고쳤는데
`settings.json` 의 Bash matcher 에 연결하지 않았다. 코드는 있는데 호출되지 않는 상태.

## 고려했으나 택하지 않은 것

- **정규식을 더 정교하게 다듬어 오탐 해결** — 3번(주석 안 FQDN)에 대해 검토했다.
  버렸다. 주석 형태가 다양해 정규식이 계속 자란다. **주석을 걷어낸 코드 뷰**를
  한 번 만들고 모든 검사를 거기서 돌리는 편이 근본적이다. 대신 예외 주석
  (`RULE-EXCEPTION`)은 코드 뷰에 남지 않으므로 원본 줄에서 따로 확인한다.
- **예외 주석 인정 범위를 "같은 줄"로 좁히기** — 예측 가능해서 좋다. 버렸다.
  메서드 위에 다는 것이 자연스러운 위치인데 인정되지 않으면 사람은 훅을 고치는
  대신 우회한다. **위 3줄**로 넓혔다.
- **RD-11(반환 형식) 검사를 훅에 유지** — 패턴이 브리틀했다. 제거했다.
  훅은 MUST 중 기계적으로 판정 가능한 것만 막는다는 원칙(`ai/rules/00-index.md`)에
  RD-11(SHOULD)은 맞지 않는다. 리뷰 에이전트에 맡긴다.
- **결함마다 개별 커밋으로 남기기** — 추적성은 좋다. 버렸다. 지금은 base 작업
  구간이라 이력의 목적이 없고, 해당 커밋에 amend 하는 편이 최종 이력이 깨끗하다.

## 확신이 낮은 부분 / 남은 위험

- **자기검증 46건이 모든 경우를 덮지 않는다.** 특히 제네릭 메서드, 애노테이션이
  붙은 선언, 여러 줄에 걸친 선언은 케이스가 없다. 실제 Java 코드가 생기는
  Phase 2에서 오탐이 더 나올 것으로 본다
- **주석 제거 방식이 문자열 리터럴 안의 `//` 를 주석으로 오인한다.**
  `String url = "http://x"` 는 `"http:` 이후가 잘린다. 이 프로젝트에서 URL 리터럴이
  드물어 지금은 문제가 없지만, 나오면 오탐이 아니라 **미탐**으로 나타난다
  (잘린 뒤쪽의 위반을 못 봄). 발견되면 그때 처리한다
- 계획서의 나머지 판정 순서에 비슷한 죽은 분기가 더 있을 수 있다.
  2.3.12(판정 순서 전수 검증)가 구현 시점에 잡도록 태스크에 명시해 두었다

## 어떻게 검증했는가

- 훅마다 **실제 JSON 입력**을 흘려 넣어 exit code 를 확인했다 (추론이 아님)
- 결함 6건 각각에 대해 **회귀 케이스를 추가**하고 46건 전부 통과를 확인
- 예외 주석 범위는 경계값(위 4줄)이 차단되는지도 확인
- 문서 전체의 상대 링크를 검사해 깨진 링크 0건 확인
- 계획서 죽은 분기는 **논리 추론**으로 찾았다. 코드가 없어 실행 검증은 불가능하며,
  Phase 2 의 2.3.12 가 실증한다
