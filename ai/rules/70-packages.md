# 패키지별 추가 규칙 (PK)

> 루트 규칙([00-index.md](00-index.md))을 먼저 읽었다고 가정한다.
> 여기는 **차이와 추가만** 적는다.

패키지 규칙이 **50줄을 넘거나 루트 규칙과 충돌**하면 그 패키지에 `CLAUDE.md`를
만들고 여기 섹션은 **링크로 대체**한다 (사본 금지).

---

## PK-0 · MUST · 패키지 루트는 `com.kafkick.waiting`

조직 규칙이다. `cy-be` 가 `com.kafkick.{api,core,storage}` 를 쓰고 **두 저장소를
합칠 가능성**이 있어 지금부터 맞춘다 — 합칠 때 패키지 이동이 가장 비싸다.
`ArchUnit`(2.8.1)이 전 클래스의 소속을 검사한다.

**영속 계층은 만들지 않는다.** `cy-be` 는 `storage/db/…/{entity,mapper,repository}`
3단이지만 게이트웨이는 재고를 차감하지 않아(비목표) 엔티티도 리포지터리도 없다.
Redis 어댑터 하나가 전부다 — **JPA 를 넣지 않는다.**

## PK · domain

**가장 엄격한 규칙이 적용된다.** 이 계층의 오류가 곧 크레딧 초과 배분과 공정성 붕괴다.

| 규칙 | 내용 |
|---|---|
| PK-D1 | Spring·Redis·Reactor·`Instant.now()`·`Math.random()` 참조 **금지** (DS-1). ArchUnit이 검사 |
| PK-D2 | 브랜치 커버리지 **100%**, 뮤테이션 생존율 **≤ 10%** |
| PK-D3 | 도달 불가 상태를 만들 수 있는 public 생성자 금지 (DS-2, JS-12) |
| PK-D4 | 모든 공개 타입에 **불변식을 Javadoc 한 줄로** 명시 |
| PK-D5 | 판정 순서를 바꾸는 변경은 **journal에 근거 필수**. 순서가 곧 우선순위다 |

### 이 패키지에서 특히 조심할 것

`IDLE ⟹ credit == 0` 은 두 값이 독립이 아니라 **같은 원인**(`waiting == 0`)에서
나온다는 뜻이다. 이 불변식을 잊으면 "credit으로 상한을 계산"하는 순간
한산한 쿠폰이 전부 큐로 간다 — 이전 구현의 핵심 버그였다.

## PK · admission

| 규칙 | 내용 |
|---|---|
| PK-A1 | 판정과 응답 작성을 **분리**한다 (DS-3). Decider는 enum만 반환 |
| PK-A2 | 판정 분기 커버리지 **100%** |
| PK-A3 | 새 판정값을 추가하면 `isPass()`/`isEnqueue()` **양쪽 다** 갱신. 누락하면 조용히 503이 나간다 |
| PK-A4 | 판정 순서 변경 시 `plan/02-domain-core.md` 3.5절 표를 **같은 커밋에서** 갱신 |
| PK-A5 | 리미터 상한 계산에 `max(1, ...)`를 쓰지 않는다 (B-2) |

## PK · allocation

| 규칙 | 내용 |
|---|---|
| PK-L1 | 배분은 **순수 함수**. Redis·시계 접근 금지 |
| PK-L2 | 총합이 `globalCredit`을 넘지 않음을 **속성 테스트**로 보장 |
| PK-L3 | 정수 나눗셈 나머지는 다음 틱으로. 반올림으로 메우지 않는다 |
| PK-L4 | 스케줄러 루프는 `repeatWhen` + 전용 스케줄러 (RX-2, RX-3) |
| PK-L5 | 게이지는 **한 번만 등록**하고 값은 필드로 갱신. 매 틱 등록하면 첫 값에 멈춘다 |

---

## PK · snapshot

| 규칙 | 내용 |
|---|---|
| PK-S1 | 스냅샷은 **불변 + 참조 통째 교체**. 부분 갱신 금지 (A-3) |
| PK-S2 | 갱신 실패 시 **기존 스냅샷을 지우지 않는다** (RX-6) |
| PK-S3 | `fetchStale`과 `dataStale`을 **절대 섞지 않는다** (A-4). 섞으면 전 노드 동시 이탈 |
| PK-S4 | 헬스체크는 `fetchStale`만 본다 (A-5) |
| PK-S5 | 항목 하나가 깨져도 나머지 판정을 포기하지 않는다 |

---

## PK · queue

| 규칙 | 내용 |
|---|---|
| PK-Q1 | 순번은 **서버만** 쓴다. 클라이언트가 보관하면 고칠 수 있는 값이 된다 |
| PK-Q2 | 폴링이 곧 하트비트. 별도 heartbeat 엔드포인트를 만들지 않는다 |
| PK-Q3 | 폴링 간격은 **서버가 지정**한다. 클라이언트에 맡기면 부하가 되레 는다 |
| PK-Q4 | 응답에 `Cache-Control: no-store`. 캐시되면 모두가 같은 순번을 본다 |
| PK-Q5 | 에러 응답의 `Retry-After`에 **지터 필수** (F7). 없으면 회복 시 동시 재시도 |
| PK-Q6 | 표시 순위는 **단조 비증가**. 위반 시 속성 테스트가 잡는다 |

## PK · capacity

| 규칙 | 내용 |
|---|---|
| PK-C1 | 자기보고의 `ts`로 신선도를 판정한다. **TTL을 믿지 않는다** (RD-5) |
| PK-C2 | 신선한 보고 0건일 때 **하한**을 적용한다. 0으로 두면 전면 차단 |
| PK-C3 | 신규 인스턴스는 **램프업**한다 (F6). 콜드 인스턴스는 여유를 과대 보고 |
| PK-C4 | 이 패키지의 데이터는 **다른 컨텍스트가 보낸 메시지**다. 신뢰하되 검증한다 |

## PK · token

| 규칙 | 내용 |
|---|---|
| PK-T1 | 검증에 Redis 왕복 **0**. 로컬 HMAC |
| PK-T2 | 시크릿 미주입 시 **기동 실패**. 약한 키로 조용히 돌지 않는다 |
| PK-T3 | **서명을 먼저 검증**한 뒤 payload를 파싱한다. 검증 전 payload는 공격자 문자열 |
| PK-T4 | 실패 사유를 나누지 않는다. 나누면 공격자에게 오라클을 준다 |
| PK-T5 | `Mac` 인스턴스를 공유하지 않는다. 스레드 안전하지 않다 |
| PK-T6 | 토큰은 **지연 발급**. 미리 만들면 이탈자 몫이 버려진다 |

## PK · redis

| 규칙 | 내용 |
|---|---|
| PK-R1 | 키 문자열은 `RedisKeys`에만 (RD-3) |
| PK-R2 | Lua는 KEYS에 없는 키를 만지지 않는다 (RD-1). 훅이 차단 |
| PK-R3 | 한 스크립트는 한 슬롯만 (RD-2) |
| PK-R4 | Lua 주석에 KEYS/ARGV 계약을 적는다 (RD-10) |
| PK-R5 | 클라이언트 입력이 키 이름에 들어가는 경로를 **전부 의심**한다 (RD-7) |

## PK · routing

| 규칙 | 내용 |
|---|---|
| PK-N1 | in-flight 감소를 **완료·에러·타임아웃·취소 전 경로**에서 보장한다 |
| PK-N2 | 카운터 누수는 그 인스턴스를 **영구 배제**시킨다. 부하 후 0 수렴을 테스트로 |
| PK-N3 | 라우팅에 `InstanceCapacity`를 쓰지 않는다. 낡은 값으로 라우팅하면 해롭다 |
| PK-N4 | 정책 교체를 전제로 **전략 패턴**으로 둔다 (P2C → peak-EWMA) |

## PK · chaos

| 규칙 | 내용 |
|---|---|
| PK-X1 | 모든 시나리오를 **진입·유지·회복** 3단계로 판정한다 |
| PK-X2 | 회복 공통 기준 RC1~RC6을 전 시나리오에 적용한다 |
| PK-X3 | **하네스를 자기검증**한다 (TS-9). 장애를 못 넣는 하네스는 전부 통과시킨다 |
| PK-X4 | 시나리오를 먼저 실패시킨 뒤 대응을 구현한다 (TS-8) |
| PK-X5 | 게이트 미달 시 **기준을 낮추지 않는다**. 계획을 고친다 |
