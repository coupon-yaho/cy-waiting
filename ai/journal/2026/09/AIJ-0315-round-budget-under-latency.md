# 레디스가 느린 날 배분 발행이 절반으로 줄었다

## 무엇을

티켓은 명령 상한 아래 지연 300ms 에서 리더는 유지되는데 발행이 멎는다고 적었다. 루프를 켠 시나리오로 재 보니
**300ms 에서는 리더부터 잃었다** — CY-847 에서 사실로 받아들인 연장 밴드다. 리더가 사는 가장 높은 지연대인
200ms(연장 상한 300ms 보다 100ms 짧다)로 옮겨 쟀다. 8초에 서로 다른 발행이 넷이었다. 한 번이라도 오르면 통과로
두던 판정은 이것을 초록으로 넘겼다.

**첫 측정은 줄을 안 세웠다.** 몫이 없어 적용이 한 번도 안 나간 회차를 쟀다. 리뷰에서 잡혀 줄을 세우고 다시 쟀다.

## 원인 셋

1. **읽기가 하나씩 기다렸다.** 틱은 가용량 읽기 → 운영값 읽기 → 회차 순이었다. 읽기마다 틱의 4분의 1 시한이라
   느린 날 틱의 절반을 먹었다
2. **쿠폰별 적용이 하나씩 나갔다.** 왕복이 쿠폰 수만큼 쌓였다
3. **스케줄러가 완료 뒤 한 틱을 통째로 쉬었다.** 회차가 1초 걸리면 주기가 2초가 된다. 1·2 를 고쳐도 발행이 그대로
   넷이었던 이유가 이것이었다

## 고친 것

- 가용량·운영값 읽기를 동시에 돌리고, 회차는 그 읽기와 **동시에** 수요를 읽는다. 나누기는 두 읽기가 끝난 뒤다.
  수요 읽기가 실패해도 운영값 읽기는 끝까지 둔다 — 처음엔 `zip` 으로 묶어 실패가 갱신을 취소했다
- 쿠폰별 적용을 열여섯까지 동시에 보낸다(레디스 어댑터 쓰기 상한과 같다). **이중 방어 하나를 걷었다** — 순차일 때는
  쿠폰마다 쓰기 직전에 리더를 다시 물었다. 옛 임기의 쓰기는 적용 스크립트의 펜스가 막는다(`옛_임기의_적용은_안_들인다`).
  사용자와 정해 펜스에 맡겼다
- 쉬는 시간을 틱에서 직전 회차 시간을 뺀 만큼으로 줄였다. 최소 4분의 1은 쉰다. 틱에서 잘린 회차도 걸린 시간을 적는다
- 회차 시간은 끝나는 신호 **전에** 적는다. `doFinally` 에 적었더니 반복이 다음 지연을 먼저 계산해 옛 값을 썼다
- **적용끼리 한 틱을 띄운다**(`ApplyPacer`). 시작 간격만 줄이면 느린 회차가 끝에 적용하고 다음 회차가 곧바로 적용해
  두 틱 몫이 1초 안에 들어간다 — 승계 때 `HandoverSpacing` 이 막는 것과 같은 두 배다. 리뷰에서 나왔다
- **차례는 회차 시한 밖에서 기다린다.** 회차 안에서 기다리면 앞 회차 읽기가 길었던 만큼 이번 회차의 시한을 먹어 발행이
  잘렸다. 스케줄러가 다음 시작을 앞 적용 + 한 틱 − 앞 회차 읽기 시간까지 미룬다. 회차 안의 대기는 흔들림만큼 남는다
- 간격은 적용을 **보낸** 시각으로 잰다. 끝난 시각으로 재면 주기가 적용 왕복만큼 더 는다. 적용 지연의 흔들림만큼 두 적용이
  한 틱보다 가까울 수 있는 것은 받아들였다

## 어떻게 검증했나

- 줄 없이: 발행 넷 → 읽기 동시만 넷 → 적용 동시·간격 맞춤 여섯 → 수요 동시까지 일곱
- 줄을 세우고 적용 간격까지 넣은 뒤: 세 번 다 발행 여섯, 들인 인원 18, 왕복 202ms
- 차례를 시한 밖으로 뺀 뒤: 세 번 다 발행 여섯, 발행 사이 최대 틈 1.31초, 예산 초과 0
- 판정은 발행 다섯 이상, 틈 2초 이하, 낡은 표본 0, 들인 인원 양수, 예산 초과 0, 리더 유지. 주입은 왕복으로 확인한다.
  초 단위 발행 시각이라 개수는 경계에서 겹쳐 흔들린다 — 틈이 주 판정이다
- `[red]` 커밋에 처음부터 초록인 특성화 시험이 섞였다(잘린 회차 간격, 비동기 상실, 기다린 차례의 표시 시각)
- **동시 적용 자체가 발행을 몇 올렸는지는 따로 안 쟀다.** 줄 없는 측정에서는 적용이 없었다

## 곁에서 나온 것

- 전체 chaos 에서 X1 이 한 번 빨갛게 나왔다. 레디스 재시작 전에 연 연결로 리스를 조작해 첫 명령이 연결 끊김으로
  터졌고 회복 판정이 연쇄로 깨졌다. 재시작 뒤 새 연결로 바꿨다

## 남은 것

- C2c 는 지연이 일정해 회차 안의 차례 대기를 거의 안 태운다. 흔들리는 지연은 안 넣었다
- 틱이 1초에 왕복이 다섯쯤이라 지연이 조금만 더 커도 한계에 닿는다. 연결 하나에 명령을 섞어 보내 배분 명령 뒤에 줄
  선 연장 명령이 시도 상한을 넘을 수 있다. 리더 명령을 따로 떼는 것은 안 했다
- 느린 레디스를 전보다 자주 두드린다 — 주기가 2초에서 약 1.3초로 줄었다
